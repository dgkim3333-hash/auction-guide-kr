# 물건카드 PPTX 표준 (npl-deck-standard)

NPL 매입·경매 물건 분석 결과를 **누가 만들어도 같은 모양·같은 순서**의 PPTX로 만든다.
분석 내용(권리·배당·세금 계산)은 다른 분석 스킬이나 사용자 지침을 따르고, 이 스킬은 **덱의 모양과 구성만** 정한다.

## 0. 작업 순서

1. 분석을 먼저 끝내고 숫자를 `_model.json` 하나에 모은다. **숫자·이름을 생성기 코드에 직접 쓰지 않는다.**
   견본: `templates/sample_model.json`(가상 데이터).
2. `templates/charts_template.py` 와 `templates/card_template.js` 를 물건 폴더로 복사한다.
   - 헬퍼(`slide` · `table` · `kpi` · `text` · `bullets` · `img` · `src` · `vlen` · `fitFs`)와 색·글꼴은 **그대로 둔다.**
   - 장 내용만 그 물건에 맞게 바꾼다. 장 순서는 아래 「2. 고정 구성」을 따른다.
3. 도표를 만든다: `python charts_template.py _model.json`
   - 결과는 `charts/` 폴더에 PNG와 `sizes.json`으로 나온다(경로는 환경변수 `CARD_CHARTS`로 바꿀 수 있다).
   - 렌더는 cairosvg를 쓰고, 없으면 Windows Edge 헤드리스를 쓴다.
4. 덱을 만든다: `node card_template.js _model.json`
   - pptxgenjs가 필요하다(`npm i -g pptxgenjs`, Windows는 `$env:NODE_PATH=(npm root -g)`).
   - 출력 경로는 `CARD_OUT`으로 바꿀 수 있다.
5. 「4. 완료 전 검사」를 통과해야 끝난다.

PPTX를 손으로 고치지 않는다. 생성기를 고쳐 다시 만든다. 덮어쓰기 전에는 `백업/`에 사본을 둔다.

## 1. 고정 규격

| 항목 | 값 |
|---|---|
| 슬라이드 | 16:9 LAYOUT_WIDE (13.33" × 7.5") |
| 글꼴 | 맑은 고딕(Malgun Gothic) 하나만 |
| 섹션 라벨 | 11pt 굵게 파랑 #1456F0, 좌상단 (예: 「관점 1 · NPL 매입」) |
| 제목 | 24pt 굵게 남색 #1E2761, **그 장의 결론 한 문장**, 한 줄. 넘치면 `fitFs`가 15pt까지 미리 줄인다. PowerPoint는 `fit:"shrink"`를 편집 전에는 적용하지 않는다 |
| 부제 | 12.5pt 회색 #4B5563 — 기준·출처·조건 |
| 「한 줄로 말하면」 | 모든 본문 장 하단(y 6.3", 높이 0.62"), 연파랑 #EEF3FF 둥근 상자, 13pt, 라벨은 파랑 굵게 |
| 바닥글 | 9pt 회색 「사건 · 물건 · 대외 배포 금지 · 쪽번호」(`meta.footer`). 출처는 8pt로 바로 위 |
| 표 | 머리 남색 흰 글자 굵게 · 짝수 행 #F7F8FA · 선 #E5E7EB 0.5pt · 12~14pt · **8행 이하** · 칸 하나에 숫자 하나 |
| 표 정렬 | **열 단위**: 첫 열과 머리글은 왼쪽. 본문에 숫자가 하나라도 있는 열은 전체 오른쪽(`table()`이 자동 판정, 예외는 `o.align`) |
| KPI 카드 | 둥근 상자 4개 가로(폭 2.9") · 라벨 13pt · 값 23pt 굵게(13pt까지 축소) · 설명 11.5pt |
| KPI 색 | 파랑(매입 상한) · 초록 #059669(배당) · 주황 #D97706(최우선·당해세) · 빨강 #DC2626(위험) |
| 표지 | 남색 전면 · 흰 큰 제목(사건번호 + 소재지) · 빨강 「대외 배포 금지」 상자 |
| 금액 | 원 단위 풀 콤마(예: 1,234,567,890원). 억·만 축약 금지(그래프 축 라벨만 예외) · 비율 옆에 금액 |
| 발표자 노트 | 모든 장 |

도표 색 규격: 인수 #DC2626 · 소멸 #8E8E93 · 말소기준 #1456F0 · 당해세·최우선변제 #D97706 · 안전 #059669.
**당해세·최우선변제는 회색 「소멸」로 그리지 않는다.** 주황 배지와 금액으로 그린다(생성기가 금액 없으면 멈춘다).

## 2. 고정 구성 (순서)

**앞 4장만 읽어도 결론이 서야 한다.**

1. 표지
2. 한눈에 보기 — KPI 4장(관점 1 매입 상한 · 예상 배당 · 최우선변제 · 관점 2 CoC) + 핵심 3줄
3. 두 관점 나란히 — 관점 1(NPL 매입 후 제3자 낙찰·배당 회수) / 관점 2(직접 낙찰·채권 상계). 행: 판정 · 핵심 금액 · 성과 · 질권대출 반영 · 먼저 닫을 것
4. 결정 전 반드시 닫을 3가지 — 항목마다 「사실 / 금액 영향 / 어디서」
5. 관점 1(NPL 매입), 이 순서로:
   - 매입 상한 산식(입력값 표 + 계산 한 줄 + 검산)
   - 회차 시나리오(도표)
   - 배당 순서(표 + 배당 폭포)
   - 최우선변제
   - 민감도(낙찰가율 ±5%p · 미확인 임차인 · 명도 지연)
   - 질권대출 반영 — 무차입 / 질권대출 사용 나란히. 제목에 두 값을 함께 쓴다
6. 권리·문건: 권리 사다리 → 문건 타임라인 → 체크리스트(위험·주의만) → 선순위 조세 판정 → **당해 연도 당해세 산출**(재산세 · 종부세를 각각 보이고 합계) → 배당요구 종기와 당해세(어느 연도 세금까지 들어가는지)
7. 시세·입찰 → 관점 2: 레버리지 · 임대 가정
8. 세금 최소 3장: 취득세(개인·법인) / 재산세·종부세 / 3열 비교(배당 회수 · 유입 개인 · 유입 법인)
9. 관점 2 다섯 장: 입지 → 고유 리스크(「리스크 / 사실 / 영향 / 확인 방법」) → 명도 → 종합 점수(100점) → 확인해야 할 것(「우선 / 항목 / 어디서 / 왜」, 완료 항목도 남긴다)
10. 출처 · 면책
11. 부록: 임차인 전원 표(10명씩) · 체크리스트 전체
12. (채권 매입 건, 덱 맨 끝) 계약일 체크리스트 → 잔금일 체크리스트(「누가」 열) → 법무사 요청 사항. **아주 중요한 것만** 넣는다

물건에 없는 쟁점의 장은 뺀다. 있는 쟁점은 같은 형식으로 장을 만든다.

## 3. 숫자가 같은 말을 해야 한다 (검산)

- 당해세·최우선변제 금액은 네 곳에서 같아야 한다: 사다리 = 배당표 = 배당 폭포 = 엑셀.
- 배당 폭포 끝 금액 = 모델의 「우리 채권 배당」. `charts_template.py`가 assert로 멈춘다.
- 「총투입 = A + B + C」처럼 구성식을 쓰면 A·B·C의 합이 표의 총투입과 같아야 한다.
- 안 맞으면 도표를 고치지 말고 원 데이터를 다시 본다.

## 4. 완료 전 검사 — 눈으로 본다

저장했다고 완료가 아니다. **전 장을 이미지로 렌더해 실제로 본다.**

- 가능하면 PowerPoint로 렌더한다. LibreOffice는 `fit:"shrink"`를 바로 적용해 PowerPoint에서 보이는 겹침을 놓친다.
- 볼 것:
  - 한글이 □로 깨졌는지(도표는 그 PC에 있는 한글 글꼴을 첫 항목으로 써야 한다 — `font_guard()`)
  - 제목이 두 줄로 내려와 부제와 겹치는지
  - KPI 값이 라벨·설명과 겹치는지
  - 표 행이 늘어 아래 글·「한 줄로 말하면」과 겹치는지
  - 한 열 안에서 정렬이 섞였는지
  - 숫자 칸이 줄바꿈되는지
  - 표가 오른쪽 여백(13.33")을 넘는지(`table()`은 `w`를 무시하고 `colW` 합을 쓴다)
  - 금액 라벨이 막대와 겹치는지
  - −0원 행
- 겹침이 보이면 생성기를 고쳐 다시 만든다. 렌더를 못 했으면 「검증 못 했다」고 말한다.

## 5. 라벨과 표기

- 사실 앞에 라벨을 붙인다:
  - [확정] 그 답변에서 직접 조회한 출처가 있다
  - [검증필요] 원본 확인 전 (들은 말은 「전언」이라고 밝힌다)
  - [추정] 가정
  - [정보부족] 자료가 없다
- 판단(매입·입찰)은 사용자가 한다. 덱은 근거·리스크·반대 시나리오를 보이고 결정을 강요하지 않는다.
- 실명·주민번호 등 개인정보가 들어간 덱은 표지에 「대외 배포 금지」를 둔다. 외부 공유용은 채무자·임차인 이름을 가린다.
