# Post-Auction Loan Simulator 스킬

낙찰 후 부동산 담보대출 시나리오를 보수·중립·공격적 3가지로 동시 비교하여 자기자본 IRR과 임계 레버리지 한도를 산출하는 스킬.

## 1. 워크플로우 개요

```
[Step 1] 입력 수집 (필수 7개 + 선택 항목)
   ↓
[Step 2] 차주 명의 유형 선택 → LTV·금리 디폴트 매핑
   ↓
[Step 3] 3가지 시나리오 가정값 자동 생성 (사용자 조정 가능)
   ↓
[Step 4] real-estate MCP 호출하여 월 원리금·현금흐름 계산
   ↓
[Step 5] 임계 LTV(DSCR=1.0) 역산
   ↓
[Step 6] 민감도 분석 (금리·공실률·매각가 ±10%)
   ↓
[Step 7] real-estate-tax-calculator 스킬 호출 (선택, 세후 IRR 시)
   ↓
[Step 8] Excel 산출물 생성 (xlsx 스킬 활용)
```

## 2. Step 1 — 입력 수집

### 2-1. 필수 입력 (7개)

사용자에게 다음을 반드시 확인해야 한다. NPL 분석 워크플로우 후속 호출인 경우 이전 결과에서 자동 추출한다.

| 항목 | 단위 | 비고 |
|---|---|---|
| **낙찰 예상가** | 원 | NPL의 경우 매입가가 아닌 낙찰가 |
| **감정가** | 원 | 시세 비교용 |
| **월 임대료(NOI)** | 원 | 공실 차감 전 100% 만실 가정. 월 관리비·세금·공실예비를 차감한 월 순영업소득(NOI) |
| **차주 명의 유형** | 선택 | 대부업체 / SPC / 개인(다주택) / 개인(1주택) / 법인사업자 |
| **시장 기준금리** | % | 사용자가 거래 은행 견적 입력. 한국은행 기준금리 아닌 **실제 적용금리**. 견적이 없으면 2-4의 ECOS 벤치마크를 쓰고 그 사실을 산출물에 적는다 |
| **대출 기간** | 년 | 5/10/15/20/30년 |
| **보유 기간** | 년 | 1/2/3/5/10년 (출구 시점) |

**금액 단위는 원이다 (2026-09-27 개정 — 대표 금액 표기 규칙: 원 단위 풀 콤마, 만·억 축약 금지).** 사용자가 「5억」「3,000만원」처럼 말해도 받자마자 500,000,000원·30,000,000원으로 환산해 쓴다.

### 2-2. 선택 입력 (디폴트 자동 적용)

| 항목 | 디폴트 | 사용자 조정 |
|---|---|---|
| 보수 시나리오 LTV | 차주 유형별 매핑표 하한 | 가능 |
| 중립 시나리오 LTV | 차주 유형별 매핑표 중간 | 가능 |
| 공격적 시나리오 LTV | 차주 유형별 매핑표 상한 | 가능 |
| 상환 방식 | 원리금균등 | 원금균등/만기일시 변경 가능 |
| 매각가 가정 (보수/중립/공격) | 낙찰가×1.05 / ×1.15 / ×1.30 | 가능 |
| 공실률 | 5% | 가능 |
| 운영비율(임대료 대비) | 15% | 사용자 조정 |

### 2-3. 입력 수집 시 주의

- 사용자가 NPL 매입가만 알려주고 낙찰가를 말하지 않으면 → "예상 낙찰가는 얼마로 가정할까요?" 반드시 확인
- 임대료가 없으면(공실 또는 용도 변경 예정) → "임대 가정 임대료를 얼마로 잡을까요? 인근 시세 조회가 필요하면 알려주세요" 안내
- 이때 인근 시세는 `real-estate` MCP의 `get_apartment_rent` / `get_villa_rent` / `get_officetel_rent` 등으로 조회 (사용자 선호도: 국토부 실거래가만 사용)

### 2-4. ECOS 금리 벤치마크 (2026-09-27 신설 — 매 시뮬레이션 필수)

`ecos` MCP `rates_snapshot` 을 **매번 새로** 호출해 아래 값을 「금리 근거」 블록으로 출력하고, Excel `1.입력가정값` 시트 상단에 같은 값을 **출처·기준월과 함께** 적는다. 기억·이전 대화·기존 엑셀의 금리 값은 근거가 아니다.

| 차주 유형 | 비교할 ECOS 계열 (신규취급액 기준) | 통계코드·항목 |
|---|---|---|
| 개인(1주택·다주택) | 예금은행 주택담보대출 | 121Y006 · BECBLA0302 |
| 법인사업자·SPC | 예금은행 기업대출 | 121Y006 · BECBLA02 |
| 대부업체 명의 | 예금은행 기업대출(하한) + 저축은행 일반대출(상한 참고) | 121Y006 · BECBLA02 / 121Y007 · BEDBMC00 |
| 2금융권 담보대출을 쓸 때 | 저축은행 주담대 · 상호금융 주담대 | 121Y007 · BEDBMC41 / BEDBMG21 |
| 공통 | 기준금리 · CD 91일 · 국고채 3년 | 722Y001 · 0101000 / 721Y001 · 2010000 / 5020000 |

쓰는 법:
- **사용자 견적이 있으면 견적을 쓴다.** ECOS는 옆에 병기해 견적이 시장 평균보다 얼마나 높은지·낮은지(%p)를 보여준다.
- **견적이 없으면** 해당 차주 유형의 ECOS 값을 「시장 기준금리」로 쓰고, 3-1 매핑표의 가산폭(+α)을 그 위에 얹는다. 산출물에 「실제 견적 아님 — ECOS 시장 평균 기반」을 적는다.
- **적용 금리가 CD 91일보다 낮으면 경고**한다(비현실적 가정).
- **민감도(Step 6) 금리 폭**: 기본 ±1.0%p 를 유지하되, 기준금리·국고채 3년의 12개월 변화폭이 1.0%p 를 넘으면 그 폭으로 넓힌다.
- 대출금리는 한 달 늦게 발표된다(9월 조회 시 7월분). 기준월을 병기하고 시장금리와 같은 시점처럼 섞지 않는다.
- `ecos` MCP 가 없거나 오류면 수치를 기억으로 채우지 말고 「미조회」로 두고 사용자 견적을 요청한다.
- 라벨: ECOS 조회값 `[확정]`(출처 `한국은행 ECOS, 통계코드, 조회일`), 매핑표 가산폭 `[검증필요]`.

## 3. Step 2 — 차주 명의 유형별 LTV·금리 매핑

차주 명의에 따라 적용 가능한 LTV·금리가 크게 다르다. 다음 디폴트 매핑표를 사용하되, **반드시 "이는 일반적 시장 기준이며 거래 은행 직접 확인 필수"라는 [검증필요] 라벨을 산출물에 명시**할 것.

### 3-1. 차주 유형별 LTV·금리 디폴트 매핑

| 차주 유형 | 보수 LTV | 중립 LTV | 공격 LTV | 보수 금리 | 중립 금리 | 공격 금리 |
|---|---|---|---|---|---|---|
| **대부업체 명의** | 40% | 50% | 60% | 시장+3.0%p | 시장+2.0%p | 시장+1.5%p |
| **SPC(대부업 자회사)** | 50% | 60% | 70% | 시장+1.5%p | 시장+1.0%p | 시장+0.5%p |
| **개인 (다주택)** | 30% | 40% | 50% | 시장+0.5%p | 시장+0.3%p | 시장+0.0%p |
| **개인 (1주택·실수요)** | 50% | 60% | 70% | 시장+0.3%p | 시장+0.0%p | 시장-0.3%p |
| **법인사업자(임대)** | 50% | 60% | 70% | 시장+1.0%p | 시장+0.5%p | 시장+0.0%p |

상세 매핑 근거 및 주의사항 → `references/borrower-ltv-rate-mapping.md`

### 3-2. 차주 유형별 추가 고려사항

- **대부업체 명의**: 일부 은행만 취급, 한도 협상 필수. 부동산 직접 보유 시 자기자본비율 규제 영향 검토
- **SPC**: 부동산 PF성으로 분류될 가능성, 회계 처리 분리 필요
- **개인**: DSR 40% 적용 여부, 다주택자 가산 적용 여부 확인
- **법인사업자**: 임대사업자 등록 여부에 따라 대출 한도 차등

## 4. Step 3 — 3가지 시나리오 가정값 자동 생성

### 4-1. 시나리오별 가정값 구성

| 항목 | 보수 | 중립 | 공격적 |
|---|---|---|---|
| LTV | 매핑표 보수 | 매핑표 중립 | 매핑표 공격 |
| 적용 금리 | 시장+α₁ | 시장+α₂ | 시장+α₃ |
| 공실률 | 10% | 5% | 2% |
| 운영비율 | 20% | 15% | 10% |
| 매각가(낙찰가 대비) | ×1.05 | ×1.15 | ×1.30 |
| 매각 비용(매각가 대비) | 5% | 4% | 3% |

### 4-2. 시나리오 해석

- **보수**: 다운사이드 리스크 점검. 이 시나리오에서도 양(+)의 IRR이면 안전
- **중립**: 가장 현실적 가정. 의사결정의 기준
- **공격적**: 업사이드 잠재력 점검. 이 시나리오에서도 IRR이 낮으면 매력 부족

## 5. Step 4 — 월 원리금·현금흐름 계산

### 5-1. real-estate MCP 호출

`calculate_loan_payment` 도구를 사용하여 시나리오별 월 원리금을 계산한다.

★ 이 도구만 **만원 단위 입력**(`principal_10k`)이다. 호출할 때만 ÷10,000 하고, 받은 값은 곧바로 ×10,000 해서 원으로 되돌린다. 산출물·챗 답변에 만원 값을 남기지 않는다.

```
입력:
  - principal_10k = 낙찰가(원) × LTV ÷ 10,000
  - annual_rate_pct = 시나리오 금리 (%)
  - years = 대출 기간

출력 (받은 즉시 ×10,000 → 원):
  - monthly_payment
  - total_interest
```

### 5-2. 월 순현금흐름 계산

```
월 임대수익(실효) = 월 임대료 × (1 - 공실률) × (1 - 운영비율)
월 이자비용 = 대출잔액 × 금리 / 12
월 원리금 = calculate_loan_payment 결과
월 순현금흐름 = 월 임대수익(실효) - 월 원리금
연간 순현금흐름 = 월 순현금흐름 × 12
```

### 5-3. DSCR (부채상환능력비율) 계산

```
DSCR = 연간 순영업소득(NOI) / 연간 부채상환액
     = (월 임대수익(실효) × 12) / (월 원리금 × 12)

판정:
  DSCR ≥ 1.25 : 안전 (은행 일반 요구 수준)
  DSCR ≥ 1.0  : 자체 상환 가능
  DSCR < 1.0  : 역레버리지 (자기자본 추가 투입 필요)
```

## 6. Step 5 — 임계 LTV(DSCR=1.0) 역산 (필수)

사용자가 가장 중요하게 보는 지표. **DSCR=1.0이 되는 LTV 한도**를 역산한다.

### 6-1. 역산 공식

```
연간 순영업소득(NOI) = 월 임대료 × (1 - 공실률) × (1 - 운영비율) × 12

DSCR = 1.0 조건:
  연간 NOI = 연간 부채상환액
  
  연간 부채상환액 = 대출원금 × PMT_factor (대출 기간·금리에 따른 상환계수)
  
  대출원금_임계 = 연간 NOI / PMT_factor
  
  임계 LTV = 대출원금_임계 / 낙찰가
```

### 6-2. PMT_factor 계산

```
PMT_factor (연간) = (월 PMT 비율 × 12) 
                 = [r/(1-(1+r)^(-n))] × 12
                 (r = 월 금리, n = 총 상환 개월수)
```

### 6-3. 산출물 표기

| 시나리오 | 적용 LTV | DSCR | 임계 LTV |
|---|---|---|---|
| 보수 | 40% | 1.85 | 74% |
| 중립 | 50% | 1.48 | 74% |
| 공격적 | 60% | 1.23 | 74% |

→ "본 물건은 LTV 74%까지는 임대수익으로 부채상환이 가능합니다" 형태로 해석 제공

## 7. Step 6 — 민감도 분석

다음 3개 변수를 각각 ±10% 변동시켜 IRR 변화를 측정한다.

### 7-1. 민감도 변수

| 변수 | 변동 범위 | 비고 |
|---|---|---|
| 적용 금리 | -1.0%p / 기준 / +1.0%p | 절대값 변동(%p) |
| 공실률 | 기준-5%p / 기준 / 기준+10%p | 시장 침체 시나리오 |
| 매각가 | -10% / 기준 / +10% | 향후 시세 변동 |

### 7-2. 민감도 매트릭스 (중립 시나리오 기준)

```
        매각가 -10%  매각가 기준  매각가 +10%
금리-1%   IRR_LL      IRR_LM       IRR_LH
금리 기준 IRR_ML      IRR_MM       IRR_MH
금리+1%   IRR_HL      IRR_HM       IRR_HH
```

가장 보수적 조합(금리+1%, 공실+10%p, 매각-10%)에서도 양(+)의 IRR이면 견고한 투자.

## 8. Step 7 — 세후 IRR (선택)

### 8-1. real-estate-tax-calculator 스킬 호출 조건

- 사용자가 "세후 IRR도 보여달라" 요청 시
- 기본은 세전 IRR로 출력하고, 산출물 하단에 "세후 IRR이 필요하면 추가 요청해주세요" 안내

### 8-2. 호출 시 전달 정보

```
- 취득세: 낙찰가 기준 (주택/비주택, 조정대상지역 여부 포함)
- 보유세: 보유 기간 동안 재산세·종부세
- 양도세: 매각가 - 낙찰가, 보유 기간(단기/장기), 명의 유형(개인/법인)
```

### 9-1. Excel 파일 구조 (5개 시트)

### 9-2. xlsx 스킬 표준 준수

- **모든 계산은 셀 수식으로 작성** (Python에서 계산해서 하드코딩 금지)
- 색상 규칙: 파랑(하드코딩 입력), 검정(수식), 녹색(다른 시트 참조), 노랑 배경(주요 가정)

- 백분율: 0.0% (소수점 1자리)
- 음수: 괄호 표기 (123)
- LibreOffice로 수식 재계산 후 #REF!, #DIV/0! 등 오류 0개 확인

## 11. 사용자 선호도 준수 사항

본 스킬은 사용자의 글로벌 선호도(userPreferences)를 반드시 따른다:

1. **확신도 라벨**: 모든 사실·수치 앞에 [확정]/[검증필요]/[추정] 라벨 표기
   - 사용자가 입력한 가정값 기반 계산 결과 → [확정]
   - 차주 유형별 LTV·금리 디폴트 → [검증필요] (시장 기준 추정값)
   - 매각가 가정 등 미래 예측 → [추정]

2. **부동산 시세 조회**: 국토부 실거래가(real-estate MCP)만 사용. KB시세·호갱노노·아실 등은 일절 조회·인용 금지.

3. **법률 용어 엄격 구분**: 명의 변경 관련 용어 혼동 금지

4. **금액 표기**: 원 단위 풀 콤마(예: 500,000,000원). 만·억 축약 금지. `real-estate` `calculate_loan_payment` 의 만원 입출력은 호출 경계에서만 환산한다(5-1)

## 12. 다른 스킬과의 연동

본 스킬은 단독 실행도 가능하지만, 다음 워크플로우의 G4(IRR 산정) 단계에서 호출되는 것이 일반적이다:

| 호출 컨텍스트 | 호출 스킬 | 본 스킬 역할 |
|---|---|---|
| NPL 매입 분석 | `npl-analysis` | 회수 시나리오 IRR 산정 |
| 신탁 NPL 매입 | `trust-npl-analysis` | 우선수익권 매입 IRR |
| 꼬마빌딩 직접 낙찰 | `small-building-auction` | 낙찰 후 자금조달 |
| 다가구·다세대 낙찰 | `residential-auction` | 임대수익 + 매각 IRR |
| 구분상가 낙찰 | `commercial-unit-auction` | 임대수익률 비교 |
| 토지 낙찰 | `land-auction` | 개발 후 매각 IRR |
