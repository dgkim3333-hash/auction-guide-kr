# PPTX 블루 디자인 시스템 (16:9)

> 「PPTX 작성」 프로젝트 지침(Design System Revision 2)을 회사·브랜드 식별 요소를 빼고 스킬로 옮긴 것. 2026-09-21.
> 원문은 §5 "Outer margins" 에서 끊겨 있었다. §5 본문 배치 패턴 A~F·§6 이후는 **미지정**이며, 지어내지 않고 §0 본문 규칙으로 대신한다.

## 발동 조건 (엄격)

사용자가 **PPTX 산출물을 명시적으로 요청**할 때만 켠다: "pptx로 만들어 줘", "슬라이드/덱 만들어 줘", "파워포인트로", ".pptx".
아래 상황에서는 켜지 않는다: 엑셀 검토, NPL·경매 분석 채팅 답변, 요약·설명, 파일 형식을 말하지 않은 보고서 요청.
발동하면 답변 첫 줄에 선언한다: **슬라이드 모드 — pptx-blue-design-system 적용.**

## 우선순위

1. `number-format-guard` (숫자 표기) > 이 규격
2. 이 규격 > `pptx-design-taste`·`design-taste-frontend`의 모든 미학 규칙 (그 둘은 안티슬롭 판정만 담당)
3. 이 규격 > 기존 NPL분석·물건카드 PPTX 색·폰트·좌표 규격. 단 **덱 구성**(장 순서·표 내용·도표 3종·한계 고지 문구)은 `npl-analysis`·`auction-property-card`·`ggi-interest-npl-scan`을 그대로 따른다.
4. 파일 조작은 `pptx` 스킬, 복합 도표는 `npl-svg-chart`.

## 0. 제작 제약

- 16:9만. 13.333" × 7.5" (1920 × 1080 px 기준). 1 inch = 144 px, 1 pt = 2 px.
- 템플릿 없음. python-pptx 또는 pptxgenjs로 처음부터 만든다.
- 로고: **없음.** 헤더 우측은 비워 둔다. 사용자가 로고 파일을 지정하면 그때만 원본 그대로(비율·색·투명도 유지, 장식 금지) 높이 ≈0.24"로 넣는다.
- 서체: **Pretendard만.** 다른 패밀리 혼용·폴백 금지. 내보낼 때 임베드.
  샌드박스에서 SVG/PNG를 만들 때는 `font-family` 첫 항목을 실재 폰트(Noto Sans CJK KR)로 두고, .pptx 텍스트만 Pretendard로 쓴다. Pretendard를 앞에 두면 한글이 □로 깨지고 에러는 나지 않는다.

## 0-A. 슬라이드 골격 — 5존 고정 좌표

| 존 | Y 범위 | 내용 | 스타일 |
|---|---|---|---|
| 헤더 스트립 | 0.40"–0.70" | 챕터명(좌) | Pretendard 600 12pt #8e8e93, 박스 상단 0.40" |
| 헤드라인 | 1.00"–1.75" | 대제목 | 700, 32–40pt, #222222, 행간 1.20, 상단 정렬 |
| 부제 | 1.75"–2.15" | 부제목 | 500, 16pt, #45515e, 행간 1.45 |
| 본문 박스 | 2.39"–6.85" | 모든 본문 요소 | 혼합 |
| 여백 완충 | 6.85"–7.05" | 비움 | — |
| 푸터 스트립 | 7.05"–7.30" | 페이지 번호(좌), 출처(우) | 500 10pt / 400 9–10pt, #8e8e93 |

좌우 여백 0.5". 세로 리듬: 헤더→헤드라인 0.30"(느슨), 헤드라인→부제 0"(붙임, 시각적 0.08~0.15"), 부제→본문 0.24"(중간).

- 헤드라인은 최대 2줄. 3줄이 필요하면 문장을 고친다. 부제 존으로 내려오지 않는다.
- **잠금 규칙.** 다섯 존의 Y는 전 슬라이드 동일. 예외는 표지·섹션 구분·마무리뿐. "본문이 길어서"는 예외가 아니다 — 내용을 쪼갠다.
- **경계.** 본문은 2.39"–6.85" 안에서만 산다. 6.85"는 벽. 본문 높이 4.46" 초과분은 분할·재구성·다음 장.

## 0-B. 밀도 규칙

본문 박스 하단을 비워 두지 않는다. 차트·도표·KPI 타일·비교표·2단 배치·보조 캡션으로 편안한 밀도로 채운다.
밀도는 경계를 이기지 못한다. 채우려고 7.0"나 2.35"로 밀면 내용이 많은 것이다 — 쪼갠다.
내용이 얇을 때: 근거를 사이드 패널로 / 본문 하단에 "So What" 콜아웃 / 헤드라인을 뒷받침하는 도표 / 주장·근거 2단 / 가로 3밴드 적층. 장식 도형·스톡 일러스트로 채우지 않는다.

## 0-C. 시각화 우선 (강한 기본값)

데이터·비교·과정·구조·관계가 있으면 산문이 아니라 시각화한다.
발동 조건: 숫자 2개 이상 비교 / 시간 추세(2~3점이어도) / 구성·비중·분포 / 과정·순서 / 범주 비교 / 개념 간 구조 / 지리·계층.
우선순위: ① 차트(막대·선·영역·산점·도넛) ② 스파크라인 KPI 타일 ③ 다이어그램(흐름·2×2·계층·깔때기) ④ 주석 이미지 ⑤ 표(개별 셀 값이 중요할 때만).
제약: 시각화는 본문 박스 안에서만 / 슬라이드당 1~2개 / 모든 차트에 제목(600 14pt)·축 라벨(400 10pt #45515e)·출처(400 9pt #8e8e93) / 글자가 9pt 아래로 내려가면 데이터가 많은 것 — 쪼갠다, 차트를 줄이지 않는다.
산문만 있는 본문은 섹션 오프너·핵심 한 줄·인용·정의에만 허용.

SVG 도표(Noto Sans CJK KR)에는 `㎡`가 있으므로 도표 이미지는 무관하다.
