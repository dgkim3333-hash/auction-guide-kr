# 온비드 공매 API 호출 스킬

## 목적

real-estate MCP 및 datagokr MCP의 온비드 도구를 **첫 호출에 성공**시키고 **표본 누락 없이** 데이터를 얻기 위한 표준 규칙.

> **검증 이력**: 2026-08-04 재산유형코드 재검증 / 2026-09-08 세 API의 역할 구분·압류재산 구조·공고일 기준 신규 판정 실측.

## ★★ 규칙 0: 세 API의 역할이 다르다 — 목적에 맞는 것을 골라라

**[확정 2026-09-08]** 이 스킬에서 가장 자주, 가장 비싸게 틀리는 지점이다.

| 도구 | 성격 | 개찰 전 물건 | 공고일 | 감정가·최저가 | 지역 필드 |
|---|---|---|---|---|---|
| `get_public_auction_items` | **입찰결과** (개찰 끝난 회차) | **없음** | 없음 | 있음 | 주소 문자열(마스킹 다수) |
| `onbid_realestate_list` | **진행중·입찰예정 물건** | **있음** | 없음 | 있음 | **구조화 필드** |
| `onbid_notice_list` | **공고 목록** | 있음(공고 단위) | **있음** | 없음 | 없음 |

### 목적별 선택

- **낙찰가·낙찰률·응찰자수 등 결과 통계** → `get_public_auction_items`
- **지금 입찰할 수 있는 물건** → `onbid_realestate_list`
- **최근에 새로 올라온 공고** → `onbid_notice_list` 로 공고일을 잡고 `onbid_realestate_list` 와 조인

### 결정적 증거 — 결과 API의 한계

김포 물건 `2026-0800-044311`(공고번호 901995) — 온비드 화면에는 회차 1~10이 공개돼 있다.

```
회차3  입찰 09-07  개찰 09-08  최저 1,318,680,000원
회차4  입찰 09-10  개찰 09-11  최저 1,186,810,000원   ← 온비드에는 있다
회차5  입찰 09-14  개찰 09-15  최저 1,068,130,000원   ← 온비드에는 있다
```

**`get_public_auction_items` 에는 회차 3까지만 존재한다.** 공고일은 2026-08-20인데 08-31 시점 응답에 이 물건이 아예 없었다(회차1 개찰이 09-01이라서).
그 결과 어느 주에 낙찰 42건 중 **10건(24%)** 이 직전 주 수집분에 없었다 = 한 번도 관측되지 않은 채 팔렸다.

## ★★ 규칙 0-1: `onbid_realestate_list` — `pvct_trgt_yn="N"` 이 필수다

**[확정 2026-09-08]** 이 파라미터를 빼면 `NO_MANDATORY_REQUEST_PARAMETERS_ERROR`(코드 11)가 난다.
**이 오류를 보고 "폐기된 도구"로 판정하면 안 된다.** 실제로는 정상 동작하며, 입찰 가능 물건을 얻는 **유일한 물건 단위 경로**다.

```python
mcp__datagokr__onbid_realestate_list(
    prpt_div_cd="0003,0005,0007",
    pvct_trgt_yn="N",            # ★필수. 빠뜨리면 코드 11
    lctn_sdnm="서울특별시",       # 시도만 넣는다
    num_of_rows=1000, page_no=1) # 끝까지 페이징
```

**[확정] 실측 total_count (2026-09-08)**: 서울특별시 6,142 / 경기도 15,933

### 왜 이 도구가 나은가

- **`lctnSdnm` · `lctnSggnm` · `lctnEmdNm` 이 구조화 필드로 온다.** 주소 문자열을 파싱할 필요가 없다. `lctn_sggnm` 을 안 넣고 시도 단위로 받아 응답 필드로 거르는 편이 안전하다.
  ※ 경기도는 `lctnSggnm` 이 `"수원시 영통구"` 처럼 구까지 붙어 온다. 시 이름으로 **시작**하면 통과시킨다.
- **`pbctStatNm` 이 `입찰준비중`·`입찰진행중`** 으로 온다. 결과 API처럼 미래분이 전부 `취소`로 나오지 않는다.
- **`usbdNft` = 유찰 횟수**가 그대로 있다. 환산식이 필요 없다(G-2 1순위).
- `cltrBidBgngDt` / `cltrBidEndDt` = 입찰기간. 같은 `cltrMngNo` 의 **향후 회차를 미리 반환**하므로 다음 회차 최저가를 추정하지 말고 실측값을 인용한다.
- 압류재산이 주소 마스킹 없이 정상적으로 나온다.

### 주의

- `apslPrcCtrsLowstBidRto` · `feeRate` 가 **거의 전량 null** 이다. 최저가율은 `lowstBidPrcIndctCont ÷ apslEvlAmt × 100` 으로 직접 계산한다.
- `apslEvlAmt` 가 **null 인 행**이 있다(신탁공매 다수). 감정가 상한 필터를 걸 때 통과시키지 마라.
- 일정 미정 행은 `cltrBidEndDt` 가 `"299901021600"` 처럼 **2999·9999년**으로 온다. 날짜로 변환하지 말고 `일정 미정` 으로 표기한다.
- 감정가 상한 파라미터가 없다. 수집 후 직접 적용한다.

## ★★ 규칙 0-2: 신규 판정은 「공고일」 기준으로 하라

**[확정 2026-09-08]** 개찰일 기준으로 신규를 판정하면 **압류재산이 통째로 사라진다.**

### 왜 그런가

캠코 압류재산은 **2주에 한 번 몰아서 개찰**한다.

```
08-27(51)   09-03(531)   ← 과거
                          09-08 · 09-09 → 압류재산 개찰 0건
09-17(2,999)  10-01(2,355)  10-08(2,257)   ← 앞으로
```

2026-09-08 실행에서 개찰일 기준 신규 110건이 나왔는데 **전부 기타일반재산이고 압류재산은 0건**이었다. 판정이 틀린 게 아니라 그 구간에 압류재산 개찰이 없었을 뿐이다.
게다가 그 110건은 개찰이 09-08·09-09라 **입찰이 이미 마감된 물건**이었다(입찰은 개찰 1~2일 전 종료). 받아도 쓸 수 없다.

### 공고일 기준 절차 [확정 실측]

```
1) onbid_notice_list 로 공고를 넓게 받는다
   cltr_type_cd="0001", prpt_div_cd="0003,0005,0007"
   opbd_dt_start = 내일,  opbd_dt_end = +6개월     ← 개찰일 창은 넓게
   num_of_rows=1000, 끝까지 페이징
2) 응답의 pbancYmd 가 원하는 구간(예: 최근 7일)인 행만 남긴다
   → 그 행들의 onbidPbancNo 집합 = 「신규공고집합」
3) onbid_realestate_list 로 물건을 받는다 (규칙 0-1)
4) 물건의 onbidPbancNo 가 「신규공고집합」에 있는 것만 남긴다
5) lctnSggnm 으로 지역 필터, dspsMthodNm=="매각" 만, (cltrMngNo,pbctCdtnNo) 중복 제거
6) 물건에 공고일·공고명·기관을 붙인다
```

**[확정] 2026-09-08 실측**: 개찰창 20260909~20270309 → 공고 5,076행 수집 → 공고일 20260902~20260908 필터 → 1,213행 / 고유 공고 233건(기타일반재산 219 · 압류재산 14) → 물건 조인 2,966 → 지역 필터 2,180 → 매각만 **2,167건**(압류재산 1,629 · 기타일반재산 538).
그중 **입찰 마감이 아직 남은 것이 2,165건(99.9%)**. 개찰일 기준으로 뽑았을 때(110건, 전부 마감)와 정반대다.

※ 압류재산 공고 14건 안에 물건 1,629건이 들어 있다. 지역본부 묶음 공고라 공고 1건이 수백 물건을 담는다(규칙 0-3). **지역 판정은 공고명이 아니라 물건의 `lctnSggnm` 으로 한다.**

## ★★ 규칙 0-3: 압류재산 공고는 「지역본부 × 차수」 묶음이다

| | 기타일반재산 0005 | 압류재산 0007 |
|---|---|---|
| 공고 단위 | **물건 1건 = 공고 1건** | **지역본부 × 차수 묶음** |
| 공고명 | `[개별매각] 경기도 광주시 오포읍 신현리 470-12 107동 201호 다세대주택` | `(경기지역본부) 2026년 제019차 압류재산 공매공고` |
| 주소 | 있음 | **없음** |
| 한 공고의 물건 수 | 1건 | 수십~수백 |

- 공고명에서 구·시 이름을 찾는 방식은 **압류재산에 통하지 않는다.** 괄호 안 지역본부명(`서울동부`·`서울서부`·`경기`·`인천`·`부산`·`대구경북`·`대전충남`·`광주전남`·`전북`·`강원`·`충북`·`경남`)으로 판정하거나, **물건 단위로 내려가 `lctnSggnm` 을 쓴다(권장)**.
- 지역본부 관할과 물건 소재지는 다를 수 있다. 인천지역본부 공고 안에 경기 물건이 들어 있는 사례를 실측했다. **물건 기준으로 걸러야 정확하다.**

### 결과 API에서 압류재산이 안 잡히는 이유 (참고)

`get_public_auction_items` 로 미래 개찰 구간을 보면 압류재산 12,710건이 **100% `취소`** 로 나오고, **83.1%가 주소 마스킹**(`인천광역시 강화군 *****`)이다. 표준 필터(낙찰·취소·수의계약가능 제외)를 거치면 0건이 된다.
→ 압류재산을 결과 API로 잡으려 하지 마라. `onbid_realestate_list` 를 쓴다.

## 절대 규칙 (Non-Negotiable)

### 규칙 1: 필수 파라미터

| 도구 | 필수 |
|---|---|
| `get_public_auction_items` / `onbid_notice_list` | `cltr_type_cd` · `prpt_div_cd` · `opbd_dt_start` · `opbd_dt_end` |
| `onbid_realestate_list` | `prpt_div_cd` · **`pvct_trgt_yn`** |

### 규칙 2: v2 신코드만 사용
v1 구코드(0101, 0201, 0301)는 **`total_count: 0` 허수 응답**을 낸다.

### 규칙 3: 불필요한 선택 파라미터 추가 금지
오류가 나도 **절대 추가하지 마라** — 결과를 과도하게 필터링한다.
`dsps_mthod_cd` · `bid_div_cd` · `pbct_stat_cd`
낙찰·유찰 구분이 필요하면 **전량을 받아 `pbctStatNm` 으로 필터링**한다.
※ `pvct_trgt_yn` 은 예외다 — `onbid_realestate_list` 에서는 **필수**다(규칙 0-1).

### 규칙 4: 날짜 형식은 yyyyMMdd만
`"20260504"` 정상 / `"2026-05-04"`·`"2026/05/04"` 금지

### ★규칙 4-1: 날짜 파라미터에 뒤 공백 1칸 [확정]
숫자만 주면 harness가 **정수로 변환**해 `Input should be a valid string` 오류가 난다.
- **해결: 값 끝에 공백 1칸.** `"20260531 "` — API가 트림하므로 결과는 동일.
- ★**앞 공백은 0건을 반환한다.** 반드시 **뒤** 공백.
- 날짜를 생략하면 기본값이 "최근 3개월"이라 **미래 개찰분이 통째로 빠진다.**

### ★규칙 4-2: 지역 파라미터 이름 [확정]
- `get_public_auction_items` → **`lctn_sdnm` / `lctn_sggnm`**. `sido`/`sgk` 를 쓰면 **오류 없이 조용히 무시되어 전국 12만건이 돌아온다.** 첫 응답 `total_count` 가 10만 단위면 이름을 틀린 것이다.
- 시도명은 공식 전체명(`"서울특별시"`, `"경기도"`). 강원·전북은 `강원특별자치도`, `전북특별자치도`.
- ★`get_public_auction_items` 는 **시 단위로만**. `"용인시 기흥구"` 결합조회는 0건이다.
- ★`onbid_realestate_list` 는 `lctn_sggnm` 을 아예 넣지 말고 응답 `lctnSggnm` 으로 거르는 편이 낫다(규칙 0-1).

### 규칙 5: 통계 목적이면 지역 필터를 쓰지 않는다
**[확정] 지역 필터를 걸면 과거 개찰건이 대량 누락된다.**

| 조회 | 12개월 | 최근 3개월 | 3개월 비중 |
|---|---:|---:|---:|
| 전국 (필터 없음) | 163,360 | 43,544 | 26.7% (정상) |
| 경기도 (시도 필터) | 5,511 | 4,196 | **76.1% (과거 소실)** |

원인: 압류재산 43,544건 중 25,555건(58.7%)이 **주소 마스킹**되어 지역 색인에서 빠진다.
- 단건 조회 → 지역 필터 가능 / **통계·계수 추정 → 지역 필터 금지**(전국 수집 후 파싱)

## 응답 필드 해석 가이드

### 회차 관련

| 필드 | 실제 의미 | 주의 |
|---|---|---|
| `usbdNft` | **유찰 횟수** | `onbid_realestate_list` 에 있다. **있으면 이걸 그대로 쓴다** |
| `feeRate` | 저감률(%) | `feeRate ÷ 10` = 압류재산의 유찰 회차(회당 10% 저감) |
| `pbctNsq` | 0005는 **실제 회차** / 0007은 **캠코 연간 공매차수**(`"033"`) | 0007에서 유찰 횟수로 쓰면 전부 틀린다 |

### ★0005의 최저가율로 물건의 「나이」를 추론하지 마라 [확정]

0005는 **최저가가 채권액 기준**이라 감정가와 무연동이다.
- **1회차부터 100% 미만**인 물건이 있다(실측: 회차1이 57.5%)
- **감정가를 초과**하는 최저가도 있다(실측: 회차1이 120.0%)
- **하루에 회차 1~5를 연속 저감**하는 신탁 공고가 있다(실측: 09-02 하루에 85.0%→79.8%)

→ "최저가율 90% 미만 = 오래 유찰된 물건"이라는 추론은 **틀렸다.** 재공고 여부는 **회차 이력**으로 판단한다.
→ 물건관리번호 앞 4자리는 **온비드 최초 등록 연도**다. `2023-...` 번호가 새 공고로 다시 나오는 것은 정상이다.

### 입찰상태(pbctStatNm)

**[확정] 결과 API는 6종**: 유찰 / 낙찰 / 입찰마감 / 수의계약가능 / 취소 / **개찰중**
**[확정] `onbid_realestate_list` 는 추가로** `입찰준비중` · `입찰진행중` 을 반환한다.

| 값 | 관점 |
|---|---|
| 입찰준비중 / 입찰진행중 | **지금 입찰 가능**. 결과 API에는 없다 |
| 유찰 | 매입 검토 대상 |
| 취소 | 압류재산 미래 회차는 결과 API에서 전부 이 상태 |
| 수의계약가능 | 유찰 반복 후 협의 매수 |
| 개찰중 | 아직 낙찰이 아니다. **낙찰로 분류하지 마라** |

★새로운 값이 나타나면 임의로 버리지 말고 **남긴 뒤 보고**한다.

### 금액·면적

`apslEvlAmt` 감정평가액 / `lowstBidPrcIndctCont` 최저입찰가(**문자열**) / `scfbAmt` 낙찰가 / `vldBddrNope` 유효응찰자수 / `lowstBidCtrsScfbPrcRto` 최저가 대비 낙찰가율(공매 계수의 표준 분모) / `landSqms`·`bldSqms` 면적 / `onbidCltrNm` 물건명(주소 포함, 압류재산은 마스킹 다수)

## 트러블슈팅

**증상 1 — `NO_MANDATORY_REQUEST_PARAMETERS_ERROR`(코드 11)**
필수 파라미터 누락(규칙 1). `onbid_realestate_list` 라면 십중팔구 **`pvct_trgt_yn="N"`** 이다. **이 오류로 도구를 폐기 판정하지 마라.**

**증상 2 — `Input should be a valid string`**
날짜를 숫자만으로 줬다. **뒤에 공백 1칸**(규칙 4-1).

**증상 3 — `total_count` 가 10만 단위**
지역 파라미터 이름을 틀렸다. **`lctn_sdnm`/`lctn_sggnm`**(규칙 4-2).

**증상 4 — `total_count: 0`**
① 구코드 사용 ② `0006`·`0011`(전 기간 0건) ③ `numOfRows` 5,000 초과 ④ 시군구에 구를 붙였다 ⑤ 날짜에 **앞** 공백

**증상 5 — 「온비드에 있는 물건인데 응답에 없다」**
규칙 0. 결과 API는 개찰 전 회차를 주지 않는다. `onbid_realestate_list` 로 확인한다.

**증상 6 — ★「압류재산이 하나도 안 나온다」**
규칙 0-2·0-3. 개찰일 기준으로 보고 있을 가능성이 가장 높다. 압류재산은 2주에 한 번 개찰하므로 그 사이엔 0건이 정상이다. **공고일 기준 + `onbid_realestate_list`** 로 바꾼다.

**증상 7 — 「신규라는데 입찰이 이미 끝났다」**
개찰일 기준으로 신규를 잡았다. 입찰은 개찰 1~2일 전에 마감된다. 규칙 0-2로 바꾼다.

**증상 8 — 과거 데이터가 이상하게 적음**
지역 필터를 쓰고 있다(규칙 5).

**증상 9 — `SERVICE KEY IS NOT REGISTERED ERROR`(코드 30) / HTTP 403**
키 미등록·만료. `.env` 에 placeholder가 들어 있던 사례가 있으니 **키 길이를 먼저 확인**한다(정상 64자 내외).
