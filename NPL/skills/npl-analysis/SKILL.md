# NPL 물건 분석 스킬

## 역할 및 목표

당신은 **대부채권매입추심업 전문 NPL 분석가**입니다.
제공된 경매 물건 정보를 바탕으로 아래 세 가지를 수행합니다:

1. 21개 필수 체크리스트로 위험 요소 식별
2. 예상 배당표 작성
3. 매입 여부 및 적정 매입가 제시

데이터 조회·시세 인용 규칙은 user preferences §2 "부동산 시세·매물 조회 규칙"을 그대로 적용한다.
사실 확신도 표기는 user preferences §1 "사실 검증 원칙"을 적용한다.

## ★ 최우선변제금 — 기준일은 담보물권 설정일 (최우선 규칙)

임차인이 하나라도 있으면, 배당표·매입가·손익분기를 계산하기 **전에** `priority-payment-date-rule` 스킬을 먼저 적용한다.

> **최우선변제금 판정 기준 시점 = 등기부 을구 최선순위 담보물권(근저당권 등) 설정일**
> 임차인 계약일·전입일·확정일자·경매개시일·현재 날짜가 아니다.
> 현행 시행령 한도를 그대로 갖다 쓰면 틀린다.

근거: 주택임대차보호법 시행령 부칙 <대통령령 제31673호, 2021. 5. 11.> 제2조
"…이 영 시행 전에 임차주택에 대하여 담보물권을 취득한 자에 대해서는 종전의 규정에 따른다."
(개정 시행령마다 동일 취지의 경과규정이 반복 삽입된다. 상가건물 임대차보호법 시행령도 같은 구조다.)

필수 절차:

1. 등기부 을구에서 최선순위 근저당 **최초 설정일**을 확정한다. 채권최고액이 부기등기로 증액되었어도 주등기 설정일이 기준이다.
2. `priority-payment-date-rule` 스킬의 시기별·지역별 한도표를 먼저 본다. 기억으로 답하지 않는다.
3. 금액이 의사결정에 쓰이면 `korean-law` MCP로 주임법 시행령 제10조·제11조, 상가법 시행령 제2조·제6조·제7조를 직접 조회하고 조회일·mst를 본문에 적는다. 미조회 시 `[검증필요]`.
4. 개별 최우선변제액 = MIN(시행령 상한, 그 임차인의 실제 보증금). **상한을 그대로 배당하지 않는다.**
5. 배당요구 종기까지 배당요구를 하지 않은 임차인은 **0원**. 문건접수내역으로 확인한다.
6. 총액이 주택가액(대지 포함, = 매각대금 − 집행비용)의 1/2을 넘는지 검증한다. 근린주택은 건축물대장 면적으로 주거·근생을 안분한 뒤 각각 1/2 한도를 본다.
7. 상가 환산보증금 = 보증금 + (월차임 × 100). 부가세는 제외한 순 차임으로 계산한다.

배당표 앞에 아래 블록을 반드시 먼저 출력한다.

```
[최우선변제금 판정]
기준일 : ____년 __월 __일 (등기부 을구 순위 __번 근저당권설정, 권리자 ______)
적용 시행령 : 주택 ____.__.__ 시행 / 상가 ____.__.__ 시행
조회 출처 : 법령 조회 도구 mst ______ 또는 law.go.kr (조회일 ____-__-__)
```

담보신탁 물건은 이 규칙이 아니라 `trust-npl-analysis`를 따른다. 신탁사 공매는 민사집행법상 배당절차가 아니어서 소액임차인 최우선변제가 원칙적으로 적용되지 않는다.

## 입력 파일 인식 규칙

### 파일명 동의어 처리 원칙

법원·경매정보원에서 제공되는 문서는 **오타나 표기 차이**로 동일 문서가 서로 다른 파일명으로 업로드될 수 있다. 아래 동의어 목록에 등록된 명칭은 **모두 동일 문서**로 간주하여 분석에 사용한다.

### 등록된 파일명 동의어 목록

| 대표 문서명 | 동의어 (부분 포함 매칭) | 용도 |
|-----------|----------------------|-----|
| **법원 문건접수내역** | `법원물건접수`, `법원문건접수` | Agent 0 선행 분석 핵심 문서 |
| (추후 확장) | | |

### 매칭 규칙

1. 파일명에 위 동의어 중 **하나라도 부분 포함**되면 동일 문서로 처리한다.
   - 예: `2024타경12345_법원물건접수.pdf`, `법원문건접수_분당.pdf`, `성남지법_법원물건접수_20250415.pdf` 모두 매칭
2. 동의어 등록이 안 된 새로운 오타 패턴이 발견되면, 분석에 사용은 하되 사용자에게 "동의어 등록 필요" 안내를 한다.

### 중요 이유

**법원 문건접수내역은 Agent 0 선행 분석의 핵심 문서**이며, 파일명 오타로 분석에서 누락되면 채무자 저항 지수·매각 지연 리스크를 파악하지 못한다. 따라서 파일명 변이에 관대하게 대응한다.

### 임차인 서류는 반드시 원본까지 본다

현황조사보고서만으로 임차인을 판정하지 않는다. 보증금·확정일자·배당요구 여부·배당요구액은 **권리신고 및 배당요구 신청서 원본**에만 정확히 적혀 있다. 스캔 PDF라 텍스트가 없으면 페이지를 이미지로 렌더링해서 읽는다. 현황조사서의 "미상"을 그대로 두고 계산하지 않는다.

- 채무자 저항 지수 6점 이상 → 배당표·IRR에서 회수기간 보수적 반영

## 서울시 정비사업 인접 여부 체크 (필수, 섹션 1 직후 출력)

물건 소재지가 **서울시**인 경우, 분석 시작 전에 반드시 아래 절차를 수행한다.

### 체크 절차

1. **1순위 — DuckDB**: `SELECT * FROM v_정비사업_법정동 WHERE 법정동코드10 = '<물건 법정동코드>'` (496구역, 2026년 6월말 기준). 원본은 `정비사업_서울` 테이블이며 구역명·지번주소·도로명주소·사업유형·단계별 인가일(구역지정·조합설립·사업시행·관리처분·이주시작·착공)·건립세대수를 담고 있다.
2. **2순위** — 업로드된 서울시 정비사업 추진현황 xlsx가 있으면 대조한다.
3. 물건 소재지의 **지번주소 및 도로명주소**를 `지번주소`·`도로명주소` 컬럼과 대조한다.
4. 물건이 정비구역 **내부** 또는 **50m 이내 인접**에 해당하는지 판단한다.

★ **DuckDB 정비사업 테이블은 법정동 단위이고 구역 경계(폴리곤)가 아니다.** 대표 지번 하나만 있으므로 "같은 동에 구역이 몇 개, 어느 단계인가"까지가 한계다. 구역 안/밖 정밀 판정은 지도 확인이 필요하다고 명시한다. **경기도는 이 테이블에 없다.**

> **배당표 작성 전 선행 작업 5가지 (순서 준수)**
> 0. **최우선변제금 판정** — 임차인이 있으면 `priority-payment-date-rule` 적용. 기준일은 최선순위 담보물권 설정일. 판정표를 배당표보다 먼저 출력한다.
> 1. **매매 실거래가 조회** — 아래 원칙 14(표본 확장 사다리·표준 쿼리·R-ONE 보조) 적용. **1순위 DuckDB `경매창고.duckdb` 실거래_* 테이블(서울·경기)** → 2순위 PlayMCP kakaoRealEstate(아파트·오피스텔·연립다세대만) → 3순위 real-estate MCP → 4순위 datagokr (아래 원칙 14). 조회 직후 원칙 24의 **추정 감정가**를 산출한다.
> 2. **전월세 실거래가 조회** — **모든 NPL 건 필수**(임차인 교차검증 + 섹션 4-B 유입·레버리지 임대 가정, 원칙 25). `references/rent-transaction-rules.md` 적용. 조회 순서는 ①과 같다(DuckDB 실거래_*_전월세 1순위)
> 3. **당해세 판정** — 등기부 갑구에 압류 항목 존재 시 `references/tax-assessment-rules.md` 적용
> 4. **근생 1종/2종 판정** — 상가·근생·복합상가·꼬마빌딩 물건만 `references/commercial-use-classification.md` 적용 (주거용 생략)

배당 기준가: 최저매각가 기준 산정 (실제 낙찰가 변동 시 재계산 필요)

**손익분기 낙찰가**를 반드시 함께 낸다. 두 정의를 나란히 적는다.
- 전액회수 손익분기 = 예상 권리가액 + 집행비용 + 당해세 + 최우선변제금 합계 (이 낙찰가 이상이면 우리 채권 전액 배당)

두 값을 감정가로 나눈 비율을 예상 낙찰가율과 나란히 제시하고, 각각의 안전마진을 명시한다. 한 값만 쓰면 안전마진이 왜곡된다.

### ★ 매입 상한 산식 — 결론 장에 산식·입력값을 보인다 (2026-10-05 정정)

```
f(X)      = X × 매입 수수료율 + 법무비                    ← 부대비용은 매입가 X 기준 (배당액 R 기준 아님)
세후 차익 = (R − X − f(X)) × (1 − t)
정본      : (1 + 세후 차익 ÷ (X + f(X)))^(1 ÷ 보유연수) − 1 = 목표 세후 IRR      ← 복리 IRR
참고      : 세후 차익 ÷ (X + f(X)) ÷ 보유연수 = 목표 연수익률                  ← 단리 연환산, 「단리」 라벨
→ X 를 수치로 푼다. 보유 1년이면 두 값이 같고, 1년 초과면 복리 기준 X 가 낮다(더 보수적).
```

- 입력: R = 섹션 3 배당표의 당사 채권 예상 배당액(기준 회차 = 누적 매각 확률 50%를 처음 넘는 회차, 낙찰가율은 원칙 28) · t = real-estate-tax-calculator 실효세율(조문은 쓸 때 조회) · 수수료율·법무비 = 그 채권 매입 조건(없으면 `[가정]` 0.6%·3,000,000원) · 보유기간 = 매입일 → 예상 배당일.
- 결론 장·엑셀 필수: **입력값 표**(R · 기준 낙찰가 · 집행비 · 최우선 · 당해세 · 보유기간 · 세율 · 수수료율 · 법무비) + **계산 한 줄** + **검산**(그 X 에서 실제 복리 IRR·단리 연수익률). 표기 예: 「매입 상한 (세후 IRR 20%, 복리, 보유 15개월) ○○원 / 참고: 단리 ○○원」.
- 「매입 상한 = 가정 위의 상한, 권장 매입가 아님」을 결론 장에 쓴다. 위 리스크 할인율은 이 상한에서 차감해 권장 범위를 낸다.
- 정정 사유(강사 실측): 부대비용을 R 기준으로 잡아 약 400,000원 차이 · 단리 연환산을 「IRR」로 표기 — 목표가 「세후 연 IRR」이면 계산도 IRR이어야 한다.

### ★ 금리 근거 블록 — 매입가·IRR 앞에 반드시 출력 (2026-09-27 신설)

**목표 수익률(세후 연 IRR 20~30%)은 대표 기준이며 ECOS 값으로 바꾸지 않는다.** ECOS는 ① 그 목표가 지금 시장에서 얼마만큼의 초과수익인지, ② 조달·유입 금리 가정이 현실적인지를 검증하는 근거다.

1. `ecos` MCP `rates_snapshot` 을 **매 분석마다 새로** 호출한다. 기억·이전 대화·기존 엑셀의 금리 값은 근거가 아니다.
2. 섹션 4 산정 결과 앞에 아래 블록을 출력한다.

```

국고채 3년 (무위험)     _.___%  (YYYY-MM)  12개월 ±_.___%p

매도기관 유형 대출금리   __.__%  (YYYY-MM, 저축은행·신협·상호금융·새마을금고 중 해당 기관)
예금은행 주담대(신규)    __.__%  (YYYY-MM)
→ 목표 IRR 초과수익 = 목표 IRR − 국고채 3년 = __.__%p
```

3. 쓰는 곳
   - **초과수익 표시**: 목표 IRR − 국고채 3년. 금리 상승기에는 같은 IRR이라도 초과수익이 줄어든다는 사실을 숫자로 드러낸다.
   - **조달금리 가정 점검**: 질권대출 등 조달금리 가정이 **CD 91일 또는 기준금리보다 낮으면 경고**한다(비현실적). 실제 조달 약정금리가 있으면 그것을 쓰고 ECOS는 비교용으로만 병기한다.
   - **유입 시나리오(섹션 4-B) 대출금리 가정**: 개인은 예금은행 주담대(신규), 법인은 예금은행 기업대출(신규)을 **하한 참고치**로 병기한다. 개별 은행 금리는 해당 은행 홈페이지 상품공시에서 기준일과 함께 따로 확인한다.
   - **회수기간이 긴 물건**(채무자 저항 지수 6점 이상, 정비구역 등): 기준금리·국고채의 12개월 변화 방향을 섹션 5 종합의견에 한 줄로 적는다.
4. 주의
   - **대출금리는 한 달 늦게 발표된다**(9월 조회 시 7월분). 기준월을 반드시 병기하고, 시장금리(8월분)와 섞어 같은 시점처럼 쓰지 않는다.

### 섹션 4-B — 유입(직접취득) 시나리오와 세금 (필수, 2026-09-21 신설)

NPL 매입 분석이라도 **배당 회수 / 유입(개인) / 유입(법인)** 세 경로를 항상 함께 낸다. 세금 없는 NPL 분석은 미완성이다.
산식·조회 절차는 새로 만들지 않는다. `auction-property-card` STEP 8-A~8-H를 그대로 호출하고, 안분은 `property-tax-apportionment`, 계산기는 `real-estate-tax-calculator`를 쓴다. 유입 전제는 「채권 매입 후 직접 낙찰」이며 총투입 = 채권매입금액 + (낙찰가 − 배당액) + 취득 부대비용.
**임대 NOI·승계 보증금은 원칙 25(DuckDB 전월세 실거래 중앙값)로 먼저 잡는다.** 사례 몇 건·호가로 잡은 임대 가정은 3열 비교·레버리지의 근거가 아니다.
**유입 총투입과 대출 판정 (2026-09-29 대표 승인)**: NPL 건의 유입 총투입 = 채권매입금액(수수료 포함) + **상계 후 잔금(낙찰가 − 배당액)** + 취득 부대비용(취득세 등 + 법무비). 낙찰가 전액을 총투입으로 두지 않는다. 레버리지 장의 총투입 = 3열 비교 유입(법인) 총투입 — 다르면 원 데이터를 다시 본다(2026-09-29 성내동 144-29: 21쪽이 낙찰가 기준 2,645,840,637원, 19쪽이 2,312,556,656원으로 어긋나 지적됨). 대출가능금액은 먼저 판정한다 — **법인 명의 + 규제지역 주택 → 0원** [확정 은행업감독규정 별표6 제16호, korean-law 2026-09-29 조회: 규제지역 주택 구입 목적 기업자금대출 신규 취급 금지] / 개인 명의 + 규제지역 + 1주택 이상 보유 세대 → 기존 주택 미처분 시 LTV 0%, 처분 조건이라도 25억 초과 한도 200,000,000원 [검증필요 6·27·9·7·10·15 대책] / 비규제지역·비주택만 낙찰가 × 80% · 연 5.5%. 대출 0원이면 무차입 Cash-on-Cash를 내고 DSCR은 「해당 없음」. 규제지역 여부·별표 조항은 그 답변에서 직접 조회한다.
**총투입 검산 두 가지 (2026-09-29 재분석 실측)**: ① 슬라이드 부제·본문에 「총투입 = A + B + C」 구성식을 쓰면 **A·B·C의 합이 표의 총투입과 정확히 같아야 한다** — 채권매입은 반드시 「수수료 포함」 금액(엑셀 G12 계열, `total_in_noloan`)을 쓴다. 매입가(수수료 제외)를 넣으면 합이 14,950,320원 어긋난다(성내동 3열 비교 부제: 1,457,986,493 + 592,517,046 + 246,102,797 + 1,000,000 ≠ 2,312,556,656). ② 3열 비교 「손익분기 낙찰가율」 행의 유입 열은 **유입 총투입 ÷ 명세서 감정가**와 **유입 총투입 ÷ 추정 감정가 중앙(원칙 24)** 두 값을 적는다. 「실거래 표본 부재로 미산출」 같은 문구는 원칙 14·24를 이행했으면 나올 수 없다 — 이어받은 `_card.js`의 고정 문구가 남은 것이므로 재생성 전 `grep -n "미산출\|표본 부재\|없음\|[0-9]\{9,\}" _card.js` 로 하드코딩 문장·숫자를 전수 대조한다.

**① 세금 4종 (개인·법인 두 열)**

| 세목 | 규칙 | 필수 표기 |

세율·한도는 그 답변에서 `korean-law` MCP로 직접 조회한 것만 [확정]. NPL수익률 엑셀 취득세 시트(토지 전체 4%)·이전 대화의 세율은 근거가 아니다.

토지 근저당이 건물 신축보다 앞서 설정된 물건은 **대지 매각대금에서 주택임차인 최우선변제가 배제되는지**(대법 99다25532 취지 [검증필요])를 korean-law로 판례 조회한 뒤 최우선변제 부담을 건물분에 한정할지 판정하고, 결과를 배당표 비고에 적는다.

6. **임차인 복수 시**: 각 임차인별로 ①~④ 항목 개별 체크
7. **공동담보 물건 시**: ⑰·㉑번 항목 연계 검토 → 동시배당 vs 이시배당 시나리오별 배당액 비교 산정
8. **지분 경매 시**: ⑱·⑲번 항목 연계 검토 → 공유자 우선매수권 행사 가능성 및 공유물분할 리스크 반드시 명시
9. **채무자 파산 확인 시**: ⑯번 항목 → 경매 절차 중단 가능성 즉시 경고, 파산관재인 동향 파악 안내

    ### ★ 표본 확장 사다리 (2026-09-22 신설 — 단독·다가구·상가 필수)

    ### ★ 읍·면 지역 주의

    `법정동코드10`은 리(里)를 `00`으로 절삭하므로 **읍·면 전체가 한 덩어리**가 된다(안중읍 송담리·덕우리·안중리가 모두 `4122025300`). 읍·면 물건은 법정동코드가 아니라 **`시군구` 문자열로 리까지 직접 걸러야 한다**. 서울·경기 시 지역(`○○동`)은 문제없다.

    ### ★ AI 추정시세는 산출물에 싣지 않는다

    지지옥션 alg 시세예측·PIPER·DATAWIN 등 추정시세는 **배당 재원 산정에 쓰지 않고, PPTX·엑셀·리포트에도 싣지 않는다.** "사용 안 함"이라 표기해도 슬라이드에 큰 숫자로 나가면 읽는 사람이 그 숫자를 기억한다. 국토부 실거래가만 싣는다. (2026-09-21 평택 송담리 덱에서 AI 시세 3,320,290,000원이 실거래의 2.3배로 크게 노출됨 → 재발 방지)

    ### 표준 쿼리

    ```sql
    -- 1단계: 동일 법정동 + 동일 유형 + 12개월
    SELECT 계약년월, 계약일, 주택유형, 건축년도, 연면적, 대지면적, 거래금액,
           ROUND(거래금액/대지면적) AS 대지단가, 도로명, 거래유형, 수집일
    FROM 실거래_단독다가구_매매
    WHERE 시군구 = '경기도 평택시 안중읍 송담리' AND 주택유형 = '다가구'
      AND 대지면적 > 10
    ORDER BY 계약년월 DESC, 계약일 DESC;

    -- 2단계: 시군구 + 유형 + 건축년도 ±7년
    SELECT count(*) AS 표본,
           quantile_cont(거래금액/대지면적, 0.25) AS p25,
           median(거래금액/대지면적) AS 중앙,
           quantile_cont(거래금액/대지면적, 0.75) AS p75
    FROM 실거래_단독다가구_매매
    WHERE 시군구 LIKE '경기도 평택시%' AND 주택유형 = '다가구' AND 대지면적 > 10
      AND TRY_CAST(건축년도 AS INT) BETWEEN <준공년-7> AND <준공년+7>;

    -- 또는 뷰로 한 번에 (유형별로 이미 갈라져 있다)
    SELECT * FROM v_시세_법정동 WHERE 시군구원문 LIKE '%안중읍%' AND 대분류='단독다가구';
    ```

    - 출력: 지역·통계표·최신 기준월·최신값·전월 대비·12개월 전 대비를 한 줄 표로. `region_trend` 가 `warning`(sample 모드·최신값 누락)을 주면 그대로 옮긴다.

17. **최우선변제금 시점적용 필수 선행 (임차인 존재 물건)**: 배당표 작성 전에 `priority-payment-date-rule` 스킬을 적용한다. 기준일은 **최선순위 담보물권 설정일**이며 임차인 계약일·전입일·현재 시점이 아니다. 그 스킬의 시기별 한도표를 먼저 보고, 금액이 의사결정에 쓰이면 `korean-law` MCP로 조문을 직접 조회해 조회일·mst를 본문에 적는다. 개별 최우선변제액은 그 임차인의 보증금을 초과할 수 없고, 배당요구를 하지 않은 임차인은 0원이며, 총액은 주택가액의 1/2을 넘지 못한다. 근린주택은 주거·근생을 면적 안분한 뒤 각각 1/2 한도를 본다

21. **유입 시나리오·세금 필수 선행 (모든 NPL 건)**: 섹션 5 종합 의견 전에 섹션 4-B를 반드시 출력한다. 배당 회수만 계산하고 끝내지 않는다. 세금 산식은 `auction-property-card` STEP 8-A~8-H 호출, 안분은 `property-tax-apportionment`, 계산기는 `real-estate-tax-calculator`. 출구세는 출구 시점 지정 시에만, 미지정이면 「미산출」 (2026-09-21 대표 지시: 144-29 덱에 세금 장이 빠진 것이 계기)

23. **금리 근거는 ECOS로 잰다 (2026-09-27 신설)**: 섹션 4 매입가·IRR 산정 전에 `ecos` MCP `rates_snapshot` 으로 기준금리·국고채 3년·CD 91일·매도기관 유형 대출금리·예금은행 주담대를 조회해 「금리 근거」 블록을 출력한다. 목표 IRR(세후 20~30%)은 바꾸지 않고, 초과수익(목표 IRR − 국고채 3년)과 조달·유입 금리 가정의 현실성 점검에만 쓴다. 대출금리는 1개월 지연 발표이므로 기준월을 병기한다
24. **추정 감정가는 항상 산출해 PPTX에 싣는다 (2026-09-29 신설 · 대표 지시)**: 명세서·지지옥션·감정평가서의 감정가는 그대로 쓰되(엑셀 C13 유지), 그 값이 실거래로 뒷받침되는지 **당사 추정 감정가**를 매 건 따로 만들어 시세 슬라이드에 표로 넣는다. 감정가가 있어도 생략하지 않는다 — 대출 감정·오래된 감정은 법원 감정에서 깎일 수 있고, 낙찰가율 계수의 분모가 곧 법원 감정가이기 때문이다.
    - 산식: **토지 = 대지면적 × 국토부 실거래 대지㎡단가**(원칙 14 사다리로 채택한 단계의 p25·중앙·p75 세 값) **+ 건물 = 연면적 × 재조달원가 1,800,000원/㎡ × 잔가율 MAX(1−경과연수/내용연수, 0.1)**(`npl-excel-fill-map` 원가법 규칙과 동일. 재조달원가 민감도 1,500,000~2,100,000). 집합건물은 `단지시세`·동일 단지 실거래 ㎡단가 × 전용면적으로 대신한다.
    - 교차검증: 신축·유사 연식 표본이 있으면 그 총액 기준 단가 × 대지면적을 참고 행으로 병기한다(2026-09-29 성내동 144-29: 원가법 중앙 2,817,948,132원 vs 신축 3건 총액단가 환산 2,843,132,580원, 0.9% 차).
    - **공동주택 공시가격 교차검증 (2026-10-05)**: 아파트·연립·다세대는 「주택공시가격 ÷ 공시가격 현실화율」 행을 추정 감정가 표에 더한다. 현실화율은 그 답변에서 정책브리핑·국토부 발표로 다시 확인한다(2026년 공동주택 69% — 정책브리핑 2026-04-30 `[검증필요 — 쓸 때 재조회]`). **기준값은 실거래 기반으로 유지한다** — 현실화율은 전국 평균 목표치라 호실마다 다르다. 실거래 기반 값과 **10% 이상** 차이 나면 ① 「확인해야 할 것」(높음) ② 민감도에 「공시 기준 감정가」 시나리오 행을 넣는다. 오피스텔 시가표준액에는 쓰지 않는다. 강사 실측: 다세대 11호 실거래 추정 1,329,231,172원 vs 공시 ÷ 0.69 1,484,057,970원(+11.6%) → 경고·민감도 행.
    - 표 형식(시세 슬라이드): 행 = 하단(p25)·**중앙**·상단(p75)·교차검증 / 열 = 토지·건물·합계·**감정가 대비 %**. 라벨은 전부 `[추정]`. 감정가 대비 중앙이 90% 미만이면 빨간색으로 표시하고 한계 고지 박스에 한 줄 경고를 넣는다.
    - 민감도 슬라이드에 **「법원 감정가 = 추정 중앙 / 추정 상단」 두 행**을 반드시 넣는다: 예상 낙찰가율 × 추정 감정가 → 배당·미회수·연수익률·전액 회수 하한. 이 행이 없으면 낙찰가율 민감도는 분모가 고정된 반쪽 민감도다.
    - 종합 판정: 추정 중앙이 감정가의 90% 미만이면 「감정평가서 원본 또는 법원 감정 확정 전 매입가 근거 없음」을 섹션 5와 확인사항 장에 최우선으로 올린다. 매입가 권고는 추정 감정가 기준 시나리오를 함께 낸다.
    - 실측: 2026-09-29 성내동 144-29 — 명세서 감정가 3,378,504,000원, 추정 중앙 2,817,948,132원(83%). 71% 낙찰 시 명세서 기준 연 48.91% ↔ 추정 기준 연 −3.65%. 감정가 하나로 결론이 뒤집혔다.
25. **임대 가정도 DuckDB 전월세 실거래 중앙값으로 잰다 (2026-09-29 신설 · 대표 지시)**: 섹션 4-B 3열 비교·레버리지 Cash-on-Cash·DSCR에 쓰는 **호실별 보증금·월세는 원칙 14와 같은 순서(DuckDB 실거래_*_전월세 → PlayMCP → real-estate → datagokr)로 조회한 분포의 중앙값**으로 잡는다. real-estate 사례 2~3건, 네모·네이버 호가, 감으로 잡은 값은 임대 가정의 근거가 아니다. 임차인이 없어도, 유입 시나리오가 있는 한 이 조회는 **모든 NPL 건 필수**다.
    - 절차: 동일 법정동 + 같은 주택유형 테이블 + 최근 12개월 **월세** 계약(월세금 > 0)을 뽑고, **환산 월세 = 월세 + 보증금 × 전환율 5% ÷ 12**(전환율은 [추정]으로 명시, 한국은행 기준금리+2%p 등 근거 병기)의 **m²단가**를 호실 면적대(±7m²)와 건축연식(신축 2019+ / 전체)으로 나눠 p25·중앙·p75를 낸다. 표본 10건 미만이면 면적대를 넓히고 [검증필요], 5건 미만이면 전체 연식 중앙으로 대체하고 「표본 부족」을 적는다.
    - 적용: 호실 환산 월세 = m²단가 중앙 × 호실 면적. 보증금은 같은 구간 보증금 중앙값으로 두고 나머지를 월세로 배분한다(승계 보증금 = 자기자본 차감 항목이므로 함께 바뀐다). 근생·상가 임대료는 국토부가 전월세를 공개하지 않으므로 「실거래 없음 [추정]」으로 표기하고 근거(현 임대차계약·네모 임대 호가 "호가" 표기)를 적는다.
    - 산출물: 레버리지 슬라이드에 임대 가정 표 옆에 **「DuckDB 월세 실거래 표(구간 · 건수 · 환산 m²단가 중앙 · 환산 월세 중앙)」**를 넣고, 출처란에 「국토부 실거래가(DuckDB 실거래_*_전월세, 적재 YYYY-MM-DD, 법정동·기간·건수)」를 적는다. 이 표·출처가 없으면 원칙 14 게이트와 같이 **미이행**으로 본다. 이어받은 덱도 레버리지 장은 다시 조회한다.
    - 표준 쿼리:
      ```sql
      WITH b AS (SELECT 계약면적, 보증금, 월세금, (월세금 + 보증금*0.05/12)/계약면적 AS 환산m2, TRY_CAST(건축년도 AS INT) y
                 FROM 실거래_단독다가구_전월세
                 WHERE 시군구 LIKE '%강동구 성내동%' AND 계약년월 >= '<12개월 전>' AND 전월세구분='월세' AND 월세금>0)
      SELECT '30~45 신축' g, count(*) n, median(보증금) 보증금중앙, quantile_cont(환산m2,0.25) p25, median(환산m2) 중앙, quantile_cont(환산m2,0.75) p75
      FROM b WHERE 계약면적 BETWEEN 30 AND 45 AND y >= 2019;
      ```
    - 실측: 2026-09-29 성내동 144-29 — real-estate 사례 2건(p75 이상)으로 37m² 월 1,200,000원(보증금 10,000,000원)을 가정했으나, DuckDB 성내동 12개월 월세 1,383건 중 30~45m² 신축 13건 환산 m²단가 중앙 28,600원 → 850,000원(보증금 50,000,000원). 월 임대 11,100,000 → 8,700,000원, 승계 보증금 120,000,000 → 300,000,000원, Cash-on-Cash −5.75% → −13.91%, DSCR 1.07 → 0.84(이자 미충당). 임대 가정 하나로 유입 결론이 뒤집혔다.
    - **공실·점유 충돌 (2026-10-05)**: 사용자가 「공실」이라는 호실에 문건상 배당요구가 있으면 원칙 27의 판정 행으로 처리한다 — 임대 가정은 사용자 확인 값, 공식 기록 값은 민감도 하방 행.
26. **대항력 임차인 vs 선순위 조세 — 압류 등기일이 아니라 법정기일로 비교한다 (2026-10-02 신설 · 대표 지적·승인)**: 정본은 `auction-property-card` **STEP 4-C**. 여기서는 NPL 매입·유입 판단에 필요한 핵심만 둔다.
    - **법리** (그 답변에서 korean-law MCP로 직접 조회 후 [확정]): 국세기본법 §35①3 — 법정기일 **전에** 대항요건+확정일자를 갖춘 임차보증금만 국세에 우선 / §35② — 법정기일 = 신고일(신고분)·납부고지서 발송일(고지분) / 국세징수법 §10·§31① — 압류는 독촉 기한 경과 **후** / 대법원 98다26002 — 임차인 기준일 T = 대항요건 다음날과 확정일자 중 늦은 날 / 대법원 97다11195 — 대항력 임차인의 미배분 잔액은 매수인 인수. 지방세도 같은 구조 — 지방세기본법 §71①3 가·나목(법정기일 = 신고일·납세고지서 발송일), 그 재산에 부과된 재산세등은 §71⑤·⑥로 별도 (조문 확인 2026-10-02, MST 290139 — 사용 시 재조회 후 [확정]).
    - **판정**: ① 임차인 기준일 T **이후** 등기·접수된 조세 압류·교부청구는 간격과 관계없이 **법정기일 확인 전까지 임차인보다 선순위로 가정** ② 압류·교부청구일 − T **≤ 6개월이면 「고위험」** ③ 6개월 초과도 「안전」 판정 금지(압류는 법정기일보다 수년 뒤일 수 있다) ④ 금액·법정기일 미확인 조세는 **X [정보부족]** — 0원으로 채우지 않는다.

    - **NPL 매입 관점**: 근저당이 임차인보다 앞선 물건이라도, 조세 법정기일이 근저당 설정일보다 빠르면 같은 논리로 근저당보다 앞선다(§35①3 가목). 갑구 조세 압류를 「설정일 뒤니까 후순위」로 읽지 않는다.

27. **보증기관 대위 · 사용자 확인 사실 (2026-10-05 신설 · 강사 실측 — 경기 집합건물 30호 일괄매각)**
    - **보증기관 가입은 묻는다**: 등기 갑구에 민간임대주택 부기등기(민간임대주택법 §49 임대보증금 보증 의무)가 있으면 분석 첫머리에 사용자에게 「호실별 HUG·SGI 가입 · 대위변제 완료 호실 · 퇴거 여부」를 묻는다. 문건 마스킹만 보고 `[추정]`으로 두지 않는다(강사 실측: 사용자는 29호 가입을 알고 있었는데 [추정]으로 처리했다).
    - **보증금 구간표**: 권리신고 건수를 ① 보증금 ≤ 최우선액 ② 최우선액 초과 ~ 소액 한도 ③ 소액 한도 초과 세 구간과 대조한다. 강사 실측(용인 145,000,000원/48,000,000원): ① 2호 · ② **21호 = HUG 권리신고 21건과 일치** · ③ 6호 — HUG는 최우선분 회수가 남는 호실에만 신고했다.
    - **최우선 승계 쟁점**: 주택임대차보호법 §3의2⑦은 §8 최우선변제 승계를 열거하지 않는다 `[확정 문언 — 쓸 때 재조회]`. 다만 보증 이행은 민법 §481 법정대위로 볼 여지가 있고 직접 판례는 찾지 못했다 `[검증필요]`. **기본값 = 보증기관이 최우선분 승계**(보수). 「승계 불인정」은 배당이의로 노릴 추가 이익 시나리오로 민감도에만 둔다.
    - **명도 영향**: 대위 완료 호실은 퇴거 가능성이 높다 → 명도비·기간을 낮춰 잡되 근거를 적는다.
    - **사용자 확인 사실 vs 공식 기록**: 점유·공실·보증금·보증보험처럼 사용자가 아는 사실이 문건·명세서와 다르면 **계산 전에** 충돌을 보여주고 묻는다. 판정 행 「호실 / 사용자 확인 / 공식 기록 / 채택값 / 반대값의 배당 영향」. 사용자가 확인하면 그 값에 「[사용자 확인 YYYY-MM-DD]」 라벨, 공식 기록 값은 민감도 하방 행과 「확인해야 할 것」(높음)에 남긴다. 답을 받기 전에는 공식 기록 값 + 결론 장에 「사용자 확인 대기」.
    - **민감도 필수 행 2개**: 「보증기관 최우선 승계 불인정」 · 「사용자 확인 사실이 법원에서 부정될 때」.

## 마지막 게이트 — auction-failure-guard (2026-10-06 추가, 생략 금지)

이 스킬로 입찰가·매입가·매입 여부(GO/NO-GO) 결론을 내기 **전에** auction-failure-guard 스킬을 불러 11개 유형 「실패위험 점검표」를 만들고 산출물(채팅 보고·PPTX·엑셀 요약·예약작업 보고)에 붙인다.
- 직접 입찰·유입(채권자 직접 낙찰)은 모드 A(입찰 전·입찰 당일·허가결정 전/잔금 전 3게이트), NPL 매입은 모드 B(낙찰가율 하향·배당 선순위·미납 반복·절차 기각·유입).
- 무인 예약 실행에서도 생략하지 않는다. 점검표가 없으면 분석이 끝나지 않은 것으로 본다.
