# 지지옥션 진행물건 승률 레이더

**예상승률을 붙이고 승률 순으로 정렬한** 엑셀을 만든다.

`ggi-newlist-collect`(신건)와 목적이 다르다. 신건은 `auction-bid-price` 가 원칙 반려하는
대상이라 승률을 붙여도 쓸 데가 없다. **이기고 살 수 있는 물건은 유찰 1~4회 구간에 있다.**

## 왜 만들었나 (2026-09-02 실측)

같은 계수·같은 가격에 **물건만 바꿔** 승률이 이만큼 갈린다.

| 조회수(DB 기준) | 표본 | 무응찰률 | 승률 |
|---|---:|---:|---:|
| 0~99 | 4,475 | 64.3% | **85.6%** |
| 100~199 | 2,241 | 45.8% | 72.0% |
| 200~399 | 812 | 34.1% | 60.0% |
| 400+ | 236 | 33.9% | 54.7% |

그런데 조회수는 지금까지 **「응찰자수를 예측하는 입력」**으로만 쓰였다
(`auction-bid-price` A-STEP 2 의 조회수 판정표). **「물건을 고르는 기준」**으로는
아무도 쓰지 않았다. 이 스킬이 그 자리를 채운다.

용도별로도 갈린다 — 임야 95.0% · 상가 90.9% · 다세대 75.6% · **아파트 41.9%**.
두 축을 겹치면 조회수가 용도보다 강하다(아파트도 조회수가 낮으면 91.2%).

## 무엇을 하지 않는가

- **가치(V)를 판정하지 않는다.** 조회수는 경쟁을 걸러 주지 물건 품질을 걸러 주지 않는다.
  아무도 안 보는 데는 이유가 있을 수 있다 — 맹지·유치권·대항력 임차인·명도 난이도.
  **조회수 게이트와 V 검증은 서로 다른 두 개의 체다. 하나만 쓰면 위험하다.**
- **입찰가를 정하지 않는다.** 표의 `입찰가율` 은 승률을 재기 위한 기준선이다.
  실제 입찰가는 `auction-bid-price` 가 상한A(실거래×0.80)·상한B를 적용해 정한다.
- **계수를 바꾸지 않는다.**

## ★★ 조회수 함정 — 두 화면이 다른 것을 센다 (2026-09-02 실측)

**이 절을 건너뛰면 이 스킬 전체가 무의미해진다.**

`ggi_sale` DB 의 조회수는 **「입찰당일결과」 화면**에서 수집된 값이다.
이 스킬이 받는 목록은 **「경매종합검색」 화면**이다. 두 값은 같은 사건에서도 크게 다르다.

같은 사건 **1,298쌍**을 대조한 결과.

```
배수(목록 ÷ DB)   중앙 11.0 · P10 10.1 · P90 13.6 · 최소 10.0 · 최대 21.3
```

**최소가 10.0 이라는 것이 결정적이다.** 시간이 흘러 조회가 쌓인 것이라면
갓 유찰된 건의 배수가 1 에 가까워야 하는데 1,298건 **전부**가 10배 이상이었다.
누적 차이가 아니라 **지표 자체가 다르다.**

실측 예 (남부11계)

| 사건 | DB(08-07 수집) | 목록(09-02) | 배수 |
|---|---:|---:|---:|
| 2025-691[1] | 101 | 1,184 | 11.7 |
| 2025-691[2] | 81 | 974 | 12.0 |
| 2023-1422 | 1,089 | 11,553 | 10.6 |

**보정하지 않으면 어떻게 되는가** — 2026-09-02 수집 1,525건 중 **1,522건이
v160plus(최저 승률)로 몰린다.** 게이트가 통째로 죽고 승률이 일괄 과소평가된다.
환산하면 v0_79 1,105 / v80_159 255 / v160plus 165 로 제대로 갈린다.

### 규칙

1. **매 회차 배수를 실측한다.** `enrich_running_list.py` 가 목록과 DB 를
   (법원계 + 사건번호)로 조인해 비율의 중앙값을 낸다
2. **고정값을 박지 않는다.** 지지옥션이 화면 정의를 바꾸면 조용히 틀린다 —
   이번에 우리가 당한 방식이 정확히 그것이다
3. **매칭 30쌍 미만이면 승률을 붙이지 않고 중단한다.** 틀린 승률보다 없는 승률이 낫다
4. **배수가 2~50 밖이면 중단한다.** 화면 정의가 바뀐 신호다. 사람이 확인한다
5. 승률표의 `사전조회수_보정`(+17) 은 **쓰지 않는다.** 그것은 DB 안에서
   직전 회차와 이번 회차를 비교해 잰 값이라 둘 다 「입찰당일결과」 화면 출신이다.
   화면이 다른 이 목록에는 적용되지 않는다

### ★ 다운로드 파일을 작업 폴더로 옮기는 법 (2026-09-09 신설·대표 승인)

크롬은 `%USERPROFILE%\Downloads` 에 내려받는다. **이 폴더는 세션의 연결 폴더가 아니다.**
대표가 설정을 바꾼 것이 아니라, 세션에 연결되는 폴더가 처음부터
작업 루트 · `00_시장데이터` · `C:\AI\NPL\백업` 세 개뿐이라 닿지 않는 것이다.
`Read`·`Glob`·bash 마운트 어느 쪽으로도 보이지 않는다.

**하면 안 되는 두 가지**

- `mcp__cowork__request_cowork_directory` 로 Downloads 를 요청하지 않는다 —
  무인 회차에서 승인 팝업은 회차를 통째로 끊는다
- 브라우저에서 gzip + base64 로 실어 나르지 않는다 —
  **안전 필터가 base64 문자열을 차단**한다(2026-09-09 실측: `[BLOCKED: Base64 encoded data]`).
  재시도해도 같다. 평문 CSV 로 옮기는 것도 40만 자를 문맥에 통과시키는 짓이라 하지 않는다

**정상 경로 — `_bridge.xlsm` 의 VBA `FileCopy`**

작업 폴더에 `_bridge.xlsm` 이 있다. 이것이 그 용도다.

```
1. file(action:'open', path:'...\지지옥션_진행물건레이더\_bridge.xlsm')
2. vba(action:'import', module_name:'MBridge', vba_code: 아래)
3. vba(action:'run', module_name:'MBridge', procedure_name:'ProbeDownload')
4. bash 로 작업 폴더에 파일이 생겼는지, 크기가 브라우저가 보고한 바이트와 같은지 확인
5. vba(action:'delete', module_name:'MBridge')
6. file(action:'close', save:false)   ← 반드시 save:false. 브릿지는 빈 채로 둔다
```

```vb
Function ProbeDownload() As String
    Dim src As String, dst As String
    src = Environ$("USERPROFILE") & "\Downloads\ggi_running_YYYYMMDD.csv"
    dst = "C:\AI\NPL\온비드\지지옥션_진행물건레이더\ggi_running_YYYYMMDD.csv"
    If Dir(src) = "" Then
        ProbeDownload = "MISSING|" & src
        Exit Function
    End If
    On Error GoTo EH
    FileCopy src, dst
    ProbeDownload = "OK|" & FileLen(dst)
    Exit Function
EH:
    ProbeDownload = "ERR|" & Err.Number & "|" & Err.Description
End Function
```

- `vba(action:'run')` 은 **반환값을 돌려주지 않는다.** 성공 판정은 함수 결과가 아니라
  **bash 로 파일 존재·크기를 읽어서** 한다. 크기가 다르면 다운로드가 잘린 것이다
- `MISSING` 이면 크롬이 다운로드를 차단한 것이다 — 위 「다운로드 차단」 항목대로 처리한다
- VBA 신뢰 설정(`Trust Center` → VBA 프로젝트 개체 모델 접근)이 꺼져 있으면 `import` 가 실패한다.
  무인 회차에서는 켤 수 없으므로 보고에 「VBA 신뢰 미허용 — CSV 이동 실패」를 적고 엑셀을 만들지 않는다

**이 우회를 없애는 방법** — 대화형 회차에서 대표가 Downloads 를 연결 폴더로 한 번 추가하면
bash 로 바로 `cp` 할 수 있어 브릿지가 필요 없어진다. 무인 회차에서 먼저 요청하지는 않는다.

입찰가율 · 승률표본 · 판정불가사유`. 출력은 **승률 높은 순**으로 정렬된다.

출력 첫머리의 **`조회수 배수 ×N.NN 실측 (매칭 N,NNN쌍)`** 줄을 반드시 읽는다.
배수가 직전 회차와 크게 다르면 화면 정의가 바뀐 것일 수 있다 — 보고에 적는다.

### ★ 저감률을 최저가율만으로 판정하지 않는다

30% 저감 2회는 **49%**, 20% 저감 3회는 **51%** 다. 허용오차 ±3 을 주면
**48~52 구간이 겹친다.** 그 구간에서 회차가 한 칸 밀리면 입찰가율이 통째로 달라진다.

저감률은 법원이 정하므로 `load_ggi_csv.저감사다리()` 로 **법원을 먼저 가른다.**
스크립트가 이미 그렇게 한다 — SQL 이나 표로 다시 짜지 않는다.

### 승률등급

`A` 85% 이상 · `B` 70~85% · `C` 70% 미만 · 공란 = 미산출.

**미산출을 0% 로 읽지 않는다.** 표본이 30건 미만이거나 저감률을 판정하지 못한 것이다.

### ★ 헤더 행 H 를 정하는 법 — 500 을 박으면 #SPILL! 이 난다 (2026-09-09 실측)

`A15` 의 스필은 **15행부터 `15+N-1` 행까지** 뻗는다. 원본 표가 그 안에 걸리면
Excel 은 스필을 포기하고 `A15` 에 **`#SPILL!`** 하나만 남긴다. 결과가 빈 게 아니라
**화면이 통째로 죽는다.**

종전 값 `500` 은 표본이 200~300건이던 **신건 레이더**(`ggi-newlist-collect`)에서 온 것이다.
이 스킬은 진행물건이라 표본이 한 자릿수 배로 크다 — **2026-09-09 실측 1,493건**,
스필이 1,507행까지 뻗어 500행 표와 정면충돌했다.

```
H = max(2000, ceil((15 + N + 200) / 1000) * 1000)
```

- 데이터 `H+1` ~ `H+N`, 보조열 `Z{H}` / `Z{H+1}~Z{H+N}`
- `N` 이 1,785건 이하면 `H = 2000` 이다. 지금까지의 표본은 전부 여기에 들어간다
- 여유 200행은 다음 회차에 물건이 늘어도 같은 `H` 를 쓰게 하려는 완충이다
- **`H` 를 회차마다 다시 계산한다.** 「지난주에 2000이었으니 2000」은 금지 —
  물건이 1,786건을 넘는 순간 조용히 #SPILL! 로 돌아간다

표를 만든 **직후** `A15` 값을 읽어 `#SPILL!`(오류코드 `-2146826243`)이 아닌지 확인한다.
스필이 죽으면 슬라이서·요약 6칸이 전부 무의미해지므로 **여기서 멈추고 H 를 다시 잡는다.**

## STEP 8 — 저장 전 검증 (건너뛰지 않는다)

호출이 `success: true` 를 돌려준 것은 증거가 아니다.

### ★ 피벗 값 필드의 number_format 인자는 조용히 무시된다

`add-value-field` 에 `number_format` 을 넘겨도 `success: true` 가 오면서
셀 서식은 `G/표준` 으로 남는다. **값 필드마다** `set-field-format` 으로 다시 건다.
그래도 **총합계 행은 `G/표준` 으로 남으므로** 그 행만 `range(set-number-format)` 으로
따로 건다. (새로고침하면 지워지므로 매 회차 다시 건다.)

### ★★ XML 패치를 ElementTree 로 하지 않는다 (2026-09-09 실측 사고·대표 승인)

3단계 XML 패치에서 두 가지가 **조용히** 파일을 깬다. 둘 다 예외도 안 나고
`zip` 이 열리기까지 해서 눈으로는 못 잡는다. **매주 같은 자리에서 밟는 지뢰다.**

**① `ET.tostring` 이 네임스페이스 prefix 를 갈아치운다**

`xml.etree.ElementTree` 는 원문의 prefix 를 버리고 `ns1`·`ns2`… 로 다시 붙인다.
XML 스펙상으로는 등가지만, **`mc:AlternateContent` 의 `Requires="sle15"` 는
prefix 를 문자열로 가리킨다.** prefix 가 바뀌면 그 선언이 통째로 사라지고
참조가 끊어져 슬라이서 그림이 깨진다.

```
원본   <xdr:wsDr xmlns:xdr=… xmlns:a=…>   선언 prefix: xdr · a · mc · sle · sle15 · a16
ET 후  <xdr:wsDr xmlns:ns1=… xmlns:ns2=…>  선언 prefix: xdr · ns1 · ns2 · ns3 · ns4
       ★ sle15 선언이 증발했는데 본문에는 Requires="sle15" 가 그대로 남는다
```

→ **drawing·chart XML 은 원문 텍스트를 정규식으로 잘라 붙인다. 파싱해서 다시 쓰지 않는다.**
`twoCellAnchor` → `absoluteAnchor` 교체도 바깥 태그만 바꾸고
안쪽(`AlternateContent`·`clientData`)은 **바이트 그대로** 옮긴다.

```python
for m in re.finditer(r"<xdr:twoCellAnchor\b[^>]*>(.*?)</xdr:twoCellAnchor>", x, re.S):
    inner = m.group(1)
    body = re.sub(r"<xdr:from>.*?</xdr:from>", "", inner, flags=re.S)
    body = re.sub(r"<xdr:to>.*?</xdr:to>",   "", body,  flags=re.S)
    new = (f'<xdr:absoluteAnchor><xdr:pos x="{x_}" y="{y_}"/>'
           f'<xdr:ext cx="{cx}" cy="{cy}"/>{body}</xdr:absoluteAnchor>')
```

교체 뒤 **선언 prefix 목록과 `Requires` 개수를 원문과 대조**한다. 하나라도 다르면 중단한다.

```python
for tag in ('xmlns:sle15=', 'xmlns:sle=', 'xmlns:mc=', 'xmlns:a16=', 'xmlns:xdr=', 'xmlns:a='):
    assert tag in newx                                  # 선언 유실
assert newx.count('Requires="sle15"') == x.count('Requires="sle15"')
assert "<xdr:from>" not in newx and "<xdr:to>" not in newx
```

`absoluteAnchor` 의 자식 순서는 **`pos` → `ext` → 개체 → `clientData`** 여야 한다.
`twoCellAnchor` 의 `editAs` 속성은 옮기지 않는다(absoluteAnchor 에 없는 속성이다).

**② `ZipInfo` 객체를 두 아카이브가 공유하면 CRC 가 깨진다**

`zout.writestr(it, d)` 에 **읽던 zip 의 `ZipInfo` 를 그대로 넘기면 안 된다.**
`writestr` 은 그 객체의 `header_offset`·`CRC`·`compress_size` 를 **제자리에서 고친다.**
같은 객체가 `zin.filelist` 에도 들어 있어 원본 쪽 중앙 디렉터리가 오염되고,
결과물을 읽을 때 `BadZipFile: Bad CRC-32 for file '[Content_Types].xml'` 이 난다.

```python
orig = {i.filename: zin.read(i.filename) for i in zin.infolist()}      # ★ 먼저 다 읽어 둔다
meta = [(i.filename, i.date_time, i.compress_type, i.external_attr) for i in zin.infolist()]
for fn, dt, ct, ea in meta:
    ni = zipfile.ZipInfo(fn, date_time=dt)      # ★ ZipInfo 를 새로 만든다
    ni.compress_type = ct
    ni.external_attr = ea
    zout.writestr(ni, 고칠것이면 고친바이트 else orig[fn])
```

**쓰면서 읽지 않는다.** 원본 바이트는 루프 전에 `{이름: bytes}` 로 통째로 받아 둔다.

**③ 임시 파일은 `/tmp` 에 두지 않는다**

같은 이름의 잔재가 남아 `PermissionError` 가 난다(2026-09-09 실측).
세션 루트(`/sessions/<이름>/`)에 회차별로 다른 이름을 쓴다.

### XML 패치 검증

부품 수·목록이 같고, 달라진 부품이 의도한 것뿐이며,
`xl/slicers/`·`xl/slicerCaches/` 가 그대로 남아야 한다. 아니면 **교체하지 않는다.**

```python
diff = [k for k in names if orig[k] != zc.read(k)]     # zin 이 아니라 미리 읽어 둔 orig 와 비교
assert set(diff) == {DRW} | {f"xl/charts/chart{i}.xml" for i in range(1, 6)}
assert zc.testzip() is None
```

- 달라진 부품이 **의도한 목록과 정확히 일치**해야 한다. 하나라도 더 있으면 교체하지 않는다
- 파일 크기가 원본보다 20% 남짓 줄어드는 것은 정상이다 — Excel 과 파이썬의 압축 수준이 달라서다.
  **크기가 아니라 부품별 바이트 비교로 판정한다**
- 교체 뒤 **Excel 로 다시 열어** 피벗·슬라이서·차트 개수와 `absoluteAnchor` 좌표를 읽어 확인한다.
  Excel 이 저장하면서 되돌려 놓지 않았는지까지 봐야 끝이다

### 파일 교체가 막힐 때 ★ (2026-09-08 개정)

OneDrive 동기화 폴더에서는 덮어쓰기가 일시적으로 거부된다(`Permission denied`).
20초쯤 기다렸다 다시 시도하면 대개 풀린다.
`~$파일명.xlsx` 이 없는데도 Excel MCP 가 「이미 열려 있다」고 하면 파일을 막 교체한 직후일 때가
많다 — 20~30초 기다렸다 한 번 더 열어 본다(2026-09-09 실측: 두 번째 시도에서 열렸다).

**`~$파일명.xlsx` 잠금 파일이 있으면 Excel 이 잡고 있는 것이다.**
Excel MCP 세션이 타임아웃되면 고아 프로세스가 남아 파일을 계속 잡는다.

종전 문구 「대표에게 파일을 닫아달라고 요청한다」는 **무인 회차에서 회차를 세운다.**
아래로 대체한다.

- **요청하고 기다리지 않는다. 승인 도구도 부르지 않는다**
- `_v2` 파일명으로 저장하고 보고에 「원본 잠김 — 다음 회차 재시도」를 적는다
- 교체 전 `_backup_{원본명}_{YYYYMMDD}_패치전.xlsx` 로 백업한다
- 백업·삭제가 `Operation not permitted` 로 막혀도 그냥 넘어가고 보고에 적는다
