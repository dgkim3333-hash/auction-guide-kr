# NPL 폴더 위생

## 이 스킬이 존재하는 이유

NPL 폴더는 몇 년에 걸쳐 쌓입니다. 마스터 엑셀 하나에 백업이 스무 개씩 붙고, 폴더를
옮기다 만 흔적이 남고, 같은 사건 서류가 두 군데에 흩어집니다. 그러다 **어느 게 최신인지
아무도 모르는 상태**가 되면, 낡은 파일로 판단을 내리는 사고로 이어집니다.

실제로 이런 일이 있었습니다. 정리하려던 폴더가 "옛날 잔재"처럼 보여 지울 뻔했는데,
대조해보니 **211개 파일이 그쪽에만 있었습니다.** NPL 분석 리포트와 사건별 등기부가
통째로 사라질 뻔했습니다. 눈으로 훑어서는 절대 알 수 없었습니다.

그래서 이 스킬의 원칙은 하나입니다. **지우기 전에 대조하고, 옮긴 뒤에 검증한다.**

## 네 가지 작업

```bash
python scripts/hygiene.py scan   --root "<폴더>"                    # 점검만
python scripts/hygiene.py tidy   --root "<폴더>" [--apply]          # 정리
python scripts/hygiene.py dup    --a "<폴더A>" --b "<폴더B>"        # 두 트리 대조
python scripts/hygiene.py verify --a "<원본>"  --b "<복사본>"        # 무결성 검증
```

### scan — 무엇이 문제인지 본다

파일을 건드리지 않습니다. 다섯 가지를 찾습니다.

- **마스터와 섞인 백업** — 백업 폴더 밖에 있는 `.bak`, `_backup`, `_백업`, `복사본`
- **의심 중복** — `파일 (1).pdf` 형태. **자동 이동하지 않습니다**
- **명명 규칙 혼재** — 같은 파일의 백업인데 규칙이 여러 개
- **잔여물** — `~$...`(오피스 임시), `.~lock...#`(비정상 종료 흔적), `.tmp`
- **경로 240자 초과** — Excel·한글이 열지 못하는 위험

### tidy — 정리한다

`--apply` 없이 실행하면 **예행연습**입니다. 무엇이 어디로 갈지만 보여줍니다.
결과를 사용자에게 보여주고 동의를 받은 뒤 `--apply`를 붙이세요.

- 백업 → 같은 위치의 `백업/` 폴더로 이동
- 잔여물 → 삭제
- 빈 폴더 → **기본값은 보존**. `--remove-empty`를 붙여야 지웁니다

같은 이름이 이미 있으면 건너뜁니다. 덮어쓰면 되돌릴 수 없기 때문입니다.

### dup — 두 폴더 트리를 대조한다

폴더를 옮기다 만 상황, 백업본과 원본이 갈라진 상황에서 씁니다.

출력은 세 갈래입니다.

- **A에만 있는 경로** 중 같은 내용이 B의 다른 위치에 있는 것 → 안전
- **B 어디에도 없는 것** → 유실 위험. 이게 핵심입니다
- **같은 경로인데 크기가 다른 것** → 버전 충돌. 어느 쪽이 최신인지 표시됩니다

### verify — 옮긴 뒤 확인한다

클라우드 동기화 폴더에서는 **복사가 조용히 잘리는 일이 실제로 발생합니다.**
파일 크기를 대조해 잘린 파일을 찾아냅니다. 대량 이동 후에는 반드시 돌리세요.

## 판정 기준을 스크립트에 둔 이유

"무엇을 백업으로 볼 것인가"는 사람마다 다릅니다. 그때그때 즉석에서 판단하면 어느 날
마스터를 백업으로 오인해 옮기는 사고가 납니다. 그래서 규칙을 스크립트 한 곳에 고정했습니다.

실측으로 걸러낸 오탐도 반영돼 있습니다.

- `개인금융채권...(20251001).rtf` — 괄호 안 날짜가 `(숫자)` 패턴에 걸림 → 숫자 2자리로 제한
- `.git`, `build`, `dist`, `node_modules` — 도구가 다시 만드는 폴더. 지우면 프로젝트가 깨짐
- `_템플릿/물건폴더_표준/01_원본서류` — 템플릿은 **비어 있는 게 정상**. 지우면 뼈대가 망가짐

## 대량 이동 절차

폴더를 통합하거나 옮길 때는 이 순서를 지키세요. 순서를 바꾸면 유실이 생깁니다.

1. `dup`으로 대조 → **유실 위험 목록 확보**
2. 그 목록만 복사 (덮어쓰기 금지, `cp -n` 상당)
3. `verify`로 크기 대조 → 잘린 파일 재복사
4. 원본은 **바로 지우지 말고 이름만 바꿔** 한 달 보존
   예: `_구버전_<원래이름>_YYYYMMDD`
5. 문제없으면 그때 삭제

4번이 중요합니다. 동기화가 끝났는지, 놓친 게 없는지는 며칠 써봐야 압니다.

## 대조는 반드시 경로 기준으로

이름만으로 대조하면 사고가 납니다. `등기.pdf`, `당사자내역.pdf` 같은 범용 파일명은
**사건마다 내용이 다른데 이름이 같습니다.** 이름 기준으로 "이미 있으니 건너뛰기"를
했다가 79개를 놓친 적이 있습니다.

`dup`은 경로를 1순위로 보고, 이름+크기는 보조 판정으로만 씁니다.

사람만 할 수 있습니다.
