### 월 1회 운영 (2026-10-02 강사 결정)

- 9/30 전량 수집 뒤 이틀 만에 다시 넓게 받다가 **IP 차단**을 당했다 — 응답 `message` 「해당 IP는 비정상적인 접속으로 보안정책에의하여 차단되었습니다」, `data.ipcheck:false`. 로그인 후에도, 화면 검색 버튼도 차단 `[확정 — 2026-10-02 실측]`. 차단 기준·해제 시점은 공개되지 않는다 `[정보부족]`
- 사이트는 매각기일을 **약 3주 앞까지만** 공개한다(2026-10-02 중앙지법 최장 10/22) `[확정]`. 그래서 날짜 범위로 신규를 거르면 그 사이 공개된 신건이 빠진다(서울 4개 법원만 66건) → 매 회차 `FROM`=오늘, `TO`=오늘+3개월로 받고 **신규는 마스터 대조로만** 거른다
- 월 1회면 그 사이 공개·매각된 신건을 못 본다 → `build_rows.py --max-yuchal 1 --exclude-known` 으로 **마스터에 없는 유찰 1회**를 함께 담아 보완한다(그 사이 낙찰된 물건만 빠진다). 같은 API 응답에 이미 들어 있어 요청 수는 늘지 않는다

## STEP 2 — `collect.js` 를 네 토막으로 실행

`collect.js` 는 `[A]`~`[D]` 네 블록이다. **JS 도구는 한 호출 약 45초 제한** `[확정 — 2026-09-29 실측]` 이라 한 번에 넣으면 끊긴다(스크립트 자체는 뒤에서 끝까지 돌지만 결과를 못 받는다).

| 블록 | 무엇 | 실행 |
|---|---|---|
| `[A]` | 법원 코드 15개 · 고정 파라미터 · `window.__req` 준비 | 그대로 1회 |
| `[B]` | 수집 루프를 **띄워 놓는다** (await 하지 않음) | `FROM`=오늘, `TO`=오늘+3개월(YYYYMMDD)로 바꿔 1회 |
| `[C]` | 진행 확인 | 60~150초 간격으로 반복 |
| `[D]` | 필요한 필드만 추려 JSON 다운로드 | 완료 조건 충족 후 1회 |

**완료 조건** — `done===true` 이고 **모든 법원 `got===tot`** 이고 `fail` 빈 배열. 하나라도 다르면 보고에 명시하고 그 법원만 다시 돈다.

### 고정 파라미터 `[확정 — 2026-09-29 실측]`

| 키 | 값 | 뜻 |
|---|---|---|
| `bidDvsCd` | `000331` | 기일입찰 |
| `mvprpRletDvsCd` | `00031R` | 부동산 |
| `cortAuctnSrchCondCd` | `0004601` | 법원 기준 검색 (법원 루프 방식) |
| `pgmId` · `cortStDvs` · `statNum` · `notifyLoc` | `PGJ151F01` · `1` · `1` · `off` | |
| `pageSize` | **50** | 100은 오류(「사용에 불편을 드려서 죄송합니다…」). 51~99 미시험 `[검증필요]` |
| `bidBgngYmd` · `bidEndYmd` | YYYYMMDD | 0929~1231 과 0929~1031 의 건수가 같았다(서울중앙 916) → 종료일은 넉넉히 |

### 응답 읽는 법 `[확정 — 2026-09-29 실측]`

- `data.dma_pageInfo.totalCnt` = **목록(목물) 행 수**, `groupTotalCount` = **물건 수**. 한 물건이 토지·건물 여러 줄로 나온다 → 반드시 `법원 + saNo + maemulSer` 로 묶는다.
- 15개 법원 서버 총건수와 수집 건수 전부 일치(합계 14,465행 · 유찰 0회 4,257행 → 3,107물건). 15개 법원 전량 **약 5~6분**.
- `inqCnt`(조회수)는 385건 중 384건이 0 → **쓰지 않는다.** 02단원 「조회수 구간」 슬라이서는 `⓪ 미제공(법원경매정보)` 한 항목으로 두고 사유를 제목행·보고에 적는다.
- 시도 판정은 **`printSt`(소재지)로 한다.** `hjguSido` 는 "평택시"·"서울" 같은 불량값이 섞인다.

### 시험하지 않은 것 `[검증필요]`

- `flbdNcntMin/Max:"0"` 으로 서버에서 유찰 0회만 거르기 (현재는 전량 받아 `yuchalCnt==="0"` 으로 거른다)
- `cortAuctnSrchCondCd:"0004602"` + `rprsAdongSdCd:"11"`(소재지 기준) — 1회 시험에서 서울중앙만 나와 신뢰 불가. **법원 루프를 쓴다**
- 서울·경기 밖 법원 코드 — 물건상세검색 화면에서 `$p.getComponentById('mf_wfm_mainFrame_sbx_rletCortOfc').getItemArray()` 로 직접 읽는다

## STEP 3 — `build_rows.py` 로 원자료 CSV

```
python build_rows.py court_newlist_raw_YYYYMMDD.json --out court_newlist_YYYYMMDD.csv --master "{작업폴더}/_기록/_마스터_신건.csv" --exclude-known --max-yuchal 1
```

하는 일 (09단원 3절·6절 규칙, `[확정 — 2026-09-29·30 실측]`):

1. `(법원, saNo, maemulSer)` 로 묶고 `yuchalCnt` 가 `--max-yuchal`(기본 0) 이하인 것만 남긴다. 「구분」 열 = 신건 / 유찰1회. 유찰 1회의 최저가는 사이트 값 그대로이며 저감률은 따로 판정하지 않는다
2. `printSt` 가 「서울」「경기」로 시작하지 않으면 제외 (실측 136건 제외)
3. 용도군 분류 — 소분류 코드로. `--usage` 로 용도군을 고른다 (**기본 전체**). 코드표 원문은 09단원 5-1절

| `--usage` | 묶음 안 소분류 | 용도군 | 용도 |
|---|---|---|---|
| 업무상업 | 20109 상가주택 · 23101 주/상용 | 업무상업 | 근린주택 |
| | 21111 업무시설 + 표시용도에 '오피스텔'만 | 업무상업 | 오피스텔(업무) |
| | 21111 업무시설, 집합 / 일반 | 업무상업 | 사무실 / 빌딩 |
| | 21104 판매시설, 집합 / 일반 | 업무상업 | 상가 / 대형판매시설 |
| | 21101 근린생활시설, 집합 / 일반 | 업무상업 | 상가 / 근린시설 |
| | 그 밖 211xx (숙박·의료·교육연구·노유자·문화집회…) | 업무상업 | 소분류 이름 그대로 (「기타상업」) |
| 주거 | 20104 | 주거 | 아파트 |
| | 20105 연립 · 20106 다세대 · 20108 빌라 | 주거 | 다세대·연립 |
| | 20101 단독 · 20102 다가구 · 20103 다중 | 주거 | 단독·다가구 |
| | 20110 오피스텔 | 주거 | 오피스텔(주거) |
| | 20111 주상복합 · 20107 기숙사 | 주거 | 주상복합 · 기숙사 |
| (전체에만) | 221xx 공장·창고… · 23102·23103 | 산업복합 | 소분류 이름 |
| 토지 | 건물 목록이 **하나도 없는** 물건 (mokGbncd 전부 01) | 토지 | 지목 (대지·임야·전·답…) 또는 「토지(복수지목)」 |
| 제외 | 30000 차량·운송장비 · 40000 기타 | — | |

   판정 순서는 위 표 순서다(업무상업 → 주거 → 산업복합 → 토지). 한 물건에 근생과 주거 코드가 섞이면 업무상업으로 간다.

   실측 (2026-09-29 15개 법원 14,465행 → 물건 10,207 → 신건·서울경기) `[확정]`:
   **전체 2,962건** = 주거 2,107 (다세대·연립 1,144 · 아파트 477 · 오피스텔(주거) 372 · 단독·다가구 100 · 주상복합 12 · 기숙사 2) / 업무상업 422 (상가 283 · 근린상가 45 · 사무실 32 · 근린주택 19 · 숙박 16 · 기타상업 22 · 오피스텔(업무) 5) / 토지 261 / 산업복합 172.
   `--usage 업무상업` 은 어제(2026-09-29)의 385건보다 **37건 많다** — 중분류 21100 전체(숙박·교육연구·노유자·문화집회·의료·위락·발전)를 「기타상업」으로 포함했기 때문이다. 02단원 지지옥션 범위와 맞추려면 그 행들을 용도 슬라이서에서 빼면 된다.

4. 열은 **02단원 3절 [1] 12열** + 슬라이서용 `시도`·`시군구`·**`용도군`** + 구간 3열(02단원 3절 [3] 라벨 그대로) + `신규` + `구분`
5. 파생 규칙: 법원 = 3-2절 약칭 + 담당계(「남부7계」) / 사건번호 = `YYYY-번호`, 같은 사건에 물건이 둘 이상이면 `[물건번호]` / 건물면적 = 집합건물은 `convAddr` 첫 ㎡, 일반건물은 층별 ㎡ 합(「연면적제외」 줄·「(현황 …)」 괄호 제외) / 토지면적 = 토지 목록 ㎡ 합 — **집합건물 대지권은 목록에 없어 0** / 정렬 = 매각기일 → 서울 먼저 → 법원 → 사건번호
6. `--master` 를 주면 02단원 2-1 키(`법원|사건번호|물건번호`)로 대조해 `신규`/`기존` 을 붙인다. **이 스크립트는 마스터를 쓰지 않는다** — 마스터 갱신은 02단원 3절 [2-1] 순서(엑셀 검사 통과 후)대로 Claude 가 한다.

## STEP 4 — 엑셀: `build_excel.py` 3단계 (Cowork·Code 어디서나 같은 파일)

양식(열·색·행 높이·슬라이서 위치)은 02단원 3절 [3]·[4] 규격이며, **스크립트에 고정**돼 있다. 손으로 다시 짜지 않는다.
2026-09-30 Cowork 와 Code 에서 각자 만든 엑셀의 양식이 달라진 것이 계기다 `[확정 — 실측]`.

| 단계 | 누가 | 명령·호출 |
|---|---|---|
| **1** | 파이썬 | `python build_excel.py stage1 court_newlist_YYYYMMDD.csv --out 신건레이더_YYYYMMDD.xlsx` — 값·헤더·서식·행높이·열폭·보조열·틀고정. 끝에 2단계용 JSON(표 범위·수식·슬라이서 9개)을 출력한다 |
| **2** | Excel MCP | `file(open)` → `table(create, sheet 탐색, range = JSON.table_range, table_name TBL_new, TableStyleMedium2)` → `range(set-formulas 탐색!C4:C9 = JSON.kpi_formulas_C4_C9)` → `range(set-formulas 탐색!A15 = JSON.spill_formula_A15)` → `slicer(create-table-slicer)` ×9 (JSON.slicers 의 name·column·position 그대로) → `range(get-values C4)` 가 행 수와 같은지 → **`file(close, save:true)`** |
| **3** | 파이썬 | `python build_excel.py patch 신건레이더_YYYYMMDD.xlsx` — 슬라이서 144×170pt 절대 좌표(다중선택 버튼 보존), 머리글을 열 이름으로, 검사 5개 통과 시에만 덮어쓴다 |

- 표 이름은 **영문 `TBL_new`** — Excel MCP 가 한글 표 이름을 만들지도 참조하지도 못한다 `[확정 — 2026-09-30 Cowork·Code 실측]`
- Excel MCP 가 없는 환경이면 1단계까지만 만들고 「표·수식·슬라이서 미생성」을 보고한다
- 조회수 구간 슬라이서는 항목 1개(`⓪ 미제공`)뿐이다 → 정상. **제목행과 카톡 보고에 사유를 적는다**
- 카톡 형식은 02단원 [6]. 사이트 이름만 「법원경매정보」로 적는다
- 마스터(`_기록\_마스터_신건.csv`) 갱신은 3단계 검사 통과 뒤에만 한다(02단원 [2-1])

## 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `[B]` 실행 후 `[C]` 가 `rows: 0` 그대로 | 물건상세검색 탭이 아님 · 로그인 만료 | STEP 1 다시, 로그인 후 재실행 |
| `[D]` 에서 `FROM is not defined` | 블록을 따로 실행하면 `[B]` 의 const 가 사라진다 | 2026-09-30 판 collect.js 는 `window.__FROM/__TO` 를 쓴다. 이전 판이면 갱신 |
| 표 생성이 `Invalid table name` | 한글 표 이름 | 영문 이름(`TBL_new`)으로 |
| 엑셀 양식이 지난번과 다르다 | 스크립트 대신 손으로 만들었다 | STEP 4 `build_excel.py` 3단계로 다시 |
| `patch` 가 FAIL | 2단계(표·슬라이서 9개) 미완료 또는 저장 안 함 | 2단계를 끝내고 `file(close, save:true)` 뒤 다시 |
| 「사용에 불편을 드려서 죄송합니다」 | pageSize 100 | 50 으로 |
| JS 도구 타임아웃 | 한 호출에 45초 넘게 넣음 | 블록을 쪼갠다. 스크립트는 뒤에서 계속 돈다 — `[C]` 로 확인 |
| JSON 다운로드가 안 생김 | 자동 다운로드 미허용 | 01단원 3단계. 허용 뒤 밀린 파일이 한꺼번에 떨어질 수 있다 → md5 로 중복 정리 |
| 조회수 슬라이서에 항목 1개 | 정상 (사이트가 제공하지 않음) | 사유를 적고 진행 |
| 응답 「해당 IP는 비정상적인 접속으로 … 차단」 | 단기간 다량 조회로 IP 차단 `[확정 — 2026-10-02 실측]` | **즉시** `window.__req = async () => null` 로 루프를 멈춘다. 재시도·재수집·진단 조회 금지. 엑셀·마스터·수집기록 손대지 않고 차단 시각·완료 법원만 보고. 해제는 강사가 화면 검색으로 확인 |
| 오피스텔이 전부 「오피스텔(주거)」다 | 정상 (법원 분류가 주거용 아래에만 둔다) | 위 NOTE. 업무용 여부는 매각물건명세서·건축물대장으로 |
| 주거·토지가 안 나온다 | `--usage 업무상업` 으로 돌렸다 | `--usage 전체` (기본값) |
| 어떤 법원 `got < tot` | 중간 실패 | 그 법원만 `[B]` 를 법원 1개로 줄여 재실행 |

## 하지 않는 것

- 요청 간격 300ms 를 줄이기 · pageSize 를 올리기 — IP 차단 사유가 된다(09단원 7절)
- 한 회차에 15개 법원 전량 수집을 두 번 하기 · 며칠 안에 다시 전량 받기 — 2026-10-02 실제로 차단됐다
- 조회수를 지어내기 — 없으면 없다고 쓴다
- 마스터를 이 스크립트에서 갱신하기 — 02단원 [2-1] 순서
- 받은 목록을 남에게 나눠 주거나 인터넷에 올리기
- 특정 물건의 입찰을 권하기
