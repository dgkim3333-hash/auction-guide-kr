# 숫자 표기 검증 가드

산출물에 숫자를 쓰는 모든 작업에서, **저장 직전**과 **완료 보고 직전**에 이 절차를 실행한다.
"서식을 적용했다"는 호출 성공 응답은 증거가 아니다. **읽어서 확인한 것만 증거다.**

---

## 1. 표기 규칙 (위반 시 즉시 자동 교정)

| 대상 | 규칙 | 서식 코드 |
|---|---|---|
| 원화 금액 | 원 단위 풀 콤마. `1,234,567,890원` | `#,##0` |
| 건수·개수·횟수 | 콤마 | `#,##0` |
| 면적 | 콤마 + 소수 2자리 | `#,##0.00` |
| 비율 | 소수 1자리 + % | `0.0"%"` |
| 날짜 | ISO | `yyyy-mm-dd` |
| 식별번호 | **콤마 금지**. 앞자리 0이면 텍스트 | `@` |

**만/억/조 축약 전면 금지.** `12.3억`, `123,456만`, `3억원 미만` 모두 위반.

식별번호에 해당하는 것: 사건번호, 공고번호, 물건관리번호, 공매번호, 공매조건번호, 사업자번호, 법인등록번호, 계좌번호, 연번, 회차.

### 축약 허용 예외 (이것만)

1. 사용자가 명시적으로 "억/만/축약"으로 써 달라고 요청
2. **그래프 축 라벨만**의 가독성 — 본문 데이터·셀 값·구간 라벨은 예외 아님
3. 외부 출처 원문 인용 (출처 병기)

### ★ 비율 옆에는 금액을 붙인다

낙찰가율·LTV·전액 회수 하한처럼 **분모가 있는 비율이 제목·KPI·표 헤더에 단독으로 나오면 위반**이다.
비율 뒤에 괄호로 환산 금액을 붙인다. 읽는 사람이 크기를 가늠하지 못하기 때문이다.

- 금지: `낙찰가율 71% 기준`, `전액 회수 하한 67.26%`
- 사용: `낙찰가율 71% (2,398,737,840원) 기준`, `전액 회수 하한 67.26% (2,272,381,790원)`

분모(감정가·최저가·낙찰가)가 슬라이드마다 다를 수 있으므로 **금액은 손으로 쓰지 않고 계산 결과값을 그대로 넣는다.**
표 본문의 민감도 행처럼 비율과 금액이 이미 같은 행에 있으면 중복 표기하지 않는다.

### 구간 라벨(bin)은 본문 데이터다

`감정가 규모대`, `청구액 구간` 같은 분류 열의 값은 셀에 저장되는 본문 데이터이므로 풀 콤마를 쓴다.

- 금지: `③ 3억~5억원`
- 사용: `③ 300,000,000~500,000,000원`

라벨이 길어져 차트 가독성이 떨어지면 **차트 종류를 가로 막대로 바꿔** 해결한다. 라벨을 줄이지 않는다.
정렬이 깨질 수 있으므로 라벨 앞에 `①②③…` 순번을 붙이고, 라벨을 바꾼 뒤에는 피벗 행 필드를 오름차순으로 재정렬한다.

### 표는 열 단위로 정렬한다 (2026-10-07 신설 — Excel 표 포함)
PPTX·Word·리포트(HTML·PDF)에 넣는 **모든 표**와 **우리가 생성하는 Excel 표**(분석 엑셀·집계표 등 생성기로 만드는 시트)에 적용한다. 물건카드·NPL 브리핑뿐 아니라 그 밖의 덱·문서·엑셀도 같다.

- 첫 열(항목명)과 머리글 행은 왼쪽.
- 그 밖의 열은 본문 칸 가운데 **하나라도 숫자(금액·비율·수량)면 그 열의 본문 전체를 오른쪽 끝에 맞춘다 — 글자 칸도 포함**한다. 예: 같은 열에 `123,456,000원`과 `분석 없음`이 있으면 둘 다 오른쪽.
- 글자만 있는 열(사실·근거·확인 방법 같은 설명 열)은 왼쪽.
- **한 열 안에서 왼쪽·오른쪽이 섞이면 위반**이다. 칸마다 「숫자면 오른쪽, 글자면 왼쪽」으로 정하지 않는다 — 그렇게 하면 `+12,340,000원`·`배당 +5,600,000원`·`-` 같은 칸만 왼쪽에 붙어 열이 들쭉날쭉해진다(강사 실측 2026-10-07).
- 숫자 판정에는 부호(`+` `-` `−`)와 단위(원·%·%p·m²(㎡)·명·호·건·점·일·m·km·배·개·회·분·년·가구·개월)를 포함한다.

생성기에서는 칸이 아니라 **열을 먼저 판정**한다. pptxgenjs 표 헬퍼 예:

```js
const num = /^[+\-−]?[\d,.]+\s?(원|%|%p|m²|㎡|명|호|건|점|일|m|km|배|개|회|분|년|가구|개월)?$/;
// 열 단위 판정: 첫 열 제외, 본문 칸 중 하나라도 숫자면 그 열 전체 오른쪽. 예외는 o.align = { 열번호: "left" | "right" }
const rightCol = rows[0].map((_, ci) => (o.align && o.align[ci]) ? o.align[ci] === "right"
  : (ci > 0 && rows.slice(1).some(r => num.test(String(r[ci]).trim()))));
// 각 칸: if (ri > 0 && rightCol[ci]) op.align = "right";   (머리글 행 ri === 0 은 왼쪽)
```

물건카드·NPL 브리핑 덱의 기준 생성기(강사 기준 생성기 — 수강생판에는 미제공, 규격은 `_템플릿\물건카드_PPTX_기준\README_기준.md`)의 `table()`에는 이 판정이 들어 있다(2026-10-07). 생성기를 새로 짤 때나 예전 물건 폴더의 `_card.js`를 이어받을 때는 `table()`에 `rightCol`이 있는지 먼저 확인하고 없으면 위 판정을 넣는다. python-pptx·docx 표도 같은 순서(열 판정 → 칸 정렬)로 만든다.

**Excel 표** — 숫자 칸은 Excel이 알아서 오른쪽에 붙이지만, 같은 열의 글자 칸(`해당 없음`·`-`·`미산출` 등)은 왼쪽에 붙어 열이 섞인다. 생성기(openpyxl)에서 `wb.save()` 직전에 표 단위 후처리를 한 번 돌린다. 표 = 머리글 행(채움색으로 식별)부터 다음 머리글 행 앞까지. 테두리 없는 칸(표 밖 주석·제목)은 건드리지 않는다.

```python
import re
NUM = re.compile(r'^[+\-−]?[\d,.]+\s?(원|%|%p|m²|㎡|명|호|건|점|일|m|km|배|개|회|분|년|가구|개월)?$')
def is_head(c): return str(c.fill.fgColor.rgb or "").endswith(NAVY)          # 머리글 채움색
def is_num(c):
    v = c.value
    if v is None or isinstance(v, bool): return False
    if isinstance(v, (int, float)): return True
    s = str(v).strip()
    if s.startswith("="): return c.number_format not in ("General", "@")      # 숫자 서식이 걸린 수식
    return bool(NUM.match(s))
def align_columns(wb):
    for ws in wb.worksheets:
        heads = [r for r in range(1, ws.max_row + 1) if is_head(ws.cell(r, 1))]
        for i, hr in enumerate(heads):
            end = heads[i + 1] - 1 if i + 1 < len(heads) else ws.max_row
            for ci in range(1, ws.max_column + 1):
                if is_head(ws.cell(hr, ci)): ws.cell(hr, ci).alignment = Alignment(horizontal="left", vertical="center")
                body = [ws.cell(r, ci) for r in range(hr + 1, end + 1)]
                body = [c for c in body if c.value is not None and c.border.left.style]   # 표 안 칸만
                right = ci > 1 and any(is_num(c) for c in body)
                for c in body: c.alignment = Alignment(horizontal="right" if right else "left", vertical="center", wrap_text=c.alignment.wrap_text)
```

Excel 예외 두 가지: ① **주어진 양식을 복사해 값만 채우는 파일**(NPL수익률_교육용.xlsx 등 — `npl-excel-fill-map`)은 양식의 정렬을 그대로 둔다. 정렬을 바꾸지 않는다. ② 피벗·슬라이서·탐색 시트(`excel-explore-sheet`)처럼 Excel이 새로고침 때 서식을 다시 쓰는 영역은 대상이 아니다. 정렬은 서식만 바꾸므로 수식·값은 그대로여야 한다 — 후처리 뒤 재계산 대조(수식 오류 0건, 핵심 값 일치)를 다시 한다.

## 2. Excel 함정 — 반드시 알고 있을 것

### 함정 A: 피벗 값 필드의 number_format 인자는 조용히 무시된다

값 필드를 추가하면서 `number_format`을 같이 넘기면 `success: true`가 돌아오는데도
실제 셀 서식은 `G/표준`으로 남는 경우가 있다.

**대응:** 값 필드를 추가한 뒤 **별도 호출**로 다시 지정한다.
`field_name`에는 원본 열 이름이 아니라 `custom_name`으로 붙인 **표시 이름**을 넣는다.

### 함정 B: 시트를 다른 파일로 복사하면 서식은 남고 참조는 깨진다

시트를 다른 파일로 옮기면

- 셀 숫자 서식: 유지됨
- 피벗 원본: `'C:\...\원본파일.xlsx'!TBL_XXX` 외부 참조로 바뀜
- 피벗차트: 일반 차트로 강등, 슬라이서: 연결 끊김
- 수식: 외부 파일 경로가 박힌 채로 남음

**대응:** 처음부터 최종 저장 위치에 파일을 만든다. 이미 옮겼다면 피벗 목록에서 `sourceData`를 확인하고,
외부 경로가 보이면 피벗·차트·슬라이서를 삭제 후 재생성한다.

### 함정 C: 표·피벗 셀에 일반 범위 서식을 걸면 새로고침 때 지워진다

숫자 서식은 **표 본문에는 범위 숫자서식**, **피벗에는 피벗 필드 서식**으로만 건다.

## 3. 저장 전 필수 검증 (건너뛰지 않는다)

### 3-1. 숫자 서식 읽기 재검증

집계·금액이 들어간 **모든 시트**에 대해 실제 서식을 읽는다.
`G/표준`이 하나라도 보이면 미적용이다. 교정 후 다시 읽어 확인한다.

### 3-2. 눈으로 확인

값 영역을 캡처해 콤마가 실제로 찍혀 있는지 본다.
숫자가 `5764346199`처럼 보이면 실패다.

### 3-3. 축약 문자열 수색

셀 값·헤더·차트 제목·KPI 라벨·시트 설명문에서 아래를 찾는다.

```
억  만원  조원  천만  백만
```

시트별로 검색하고, 발견되면 원 단위 풀 콤마로 교정한다.
(주소의 `만안구`·`성남시` 같은 지명 오탐은 제외)

### 3-4. 총합계 대조

피벗 총합계 = 원자료 행 수인지 확인한다. 불일치하면 보고한다.

### 3-5. 표 정렬 확인 (PPTX·Word·리포트·Excel)
슬라이드·문서를 렌더해 표마다 본다. **한 열 안에서 왼쪽·오른쪽이 섞인 칸이 있으면 실패**다 — 생성기의 표 헬퍼가 칸 단위 판정(옛 판)이다. PPTX를 손으로 고치지 않고 헬퍼를 열 단위 판정으로 바꿔 다시 만든다. 부호가 붙은 금액(`+…원`)과 `-`만 있는 칸이 같은 열의 다른 숫자와 같은 쪽에 붙었는지 특히 본다.
Excel은 저장한 파일을 openpyxl로 다시 열어 표마다 열별 `alignment.horizontal` 값이 한 가지인지 **읽어서** 센다(혼용 열 0개여야 통과). 화면 캡처가 되면 눈으로도 본다. 캡처가 실패하면 「화면은 못 봤다」고 쓴다.

## 4. 보고 원칙

- 검증하지 않은 항목을 "확인했다"고 쓰지 않는다.
- "금액 열은 전부 콤마" 같은 문장은 **3-1과 3-2를 실제로 수행한 뒤에만** 쓴다.
- 검증 범위를 명시한다. 예: "원자료 J~M열, 피벗집계 6개 피벗 값 필드 서식을 읽어 확인"
- 검증하지 못한 부분이 있으면 그대로 밝힌다.

## 5. 셀프 체크리스트

- [ ] 피벗 값 필드마다 서식을 별도로 걸었는가
- [ ] 스크린샷에서 콤마가 눈에 보이는가
- [ ] 억/만/조 문자열을 검색했는가 (셀·헤더·차트 제목·구간 라벨 전부)

- [ ] 피벗 `sourceData`가 외부 파일 경로가 아닌가
- [ ] 피벗 총합계가 원자료 건수와 일치하는가
- [ ] 표 정렬: 표마다 한 열 안에서 왼쪽·오른쪽이 섞인 칸이 없는가 (숫자가 하나라도 있는 열은 글자 칸까지 오른쪽)
